本轮修掉的三个脚本缺陷（都不是产品代码）#

文件缺陷修法
khy_run_all.ps1 step 0WiFi 防护只认 IP:PORT（-match ':$'），漏判 mDNS/TLS 形态，于是把 WiFi 设备当 USB 放行，一路跑到断网项——正是会把手机双射频搞掉的那条路。khy_install.ps1:35 早就会匹配三种形态，只有编排器漏了改成正向判据：USB 序列号是纯令牌，凡带点号/冒号/空白的都是网络传输。阳性对照已验证（现在对该设备明确拒绝并 exit 1）
khy_accept2.ps1 序列号选择取 $d[0]，而 mDNS 重复注册名 adb-XXXX (2)._adb-tls-connect._tcp 带空格，adb -s 对它报 device not found——设备就在眼前却全盘失败先改成「跳过含空白的序列号」，又错了：哪个注册当前可用会随时间翻转，那一版只剩空格注册可用时反而报 FATAL: no device。最终改为按 adb -s <s> get-state 探针选取，不看名字形态
fake-adb-test.ps1 固件假 adb 的 pull 处理器无视目标参数、永远写 console_history.jsonl，而驱动 pull 到 console_history_probe.jsonl（khy_accept2.ps1:184）→ 驱动读到不存在的探针文件 → 21 条全报 NOT RECORDED → ts 过滤器根本没被检验到，却让第三条断言翻红（铁律 4 又一例）让假 adb 按 $args 里的目标路径复制。重跑尚未做——两者共用同一探针文件，不能与真机跑查并发

另有一个纯陷阱文件：D:\Portable\4-output\Temp\khy_devcheck.ps1（下划线）带 348 个
非 ASCII 字节且无 BOM，PowerShell 5.1 按 GBK 解码后中文注释与下一行的 $dev = ... 赋值
被并成同一行，# 把赋值整行注释掉 → 永远报 NO DEVICE。canonical 版是连字符的
khy-devcheck.ps1（纯 ASCII，HANDOFF §六一直写的是它）。我今天敲错成下划线版，

最重要：验收驱动的判定从来没有对过（2026-11-16 14:4x）#

khy_accept2.ps1 有两个 bug，任何一个都足以让全部 21 条判定失效。它们一直在，
所以本文档此前所有基于该脚本输出的结论——包括「成功率约 1/3」「两个 App 侧偶发竞态」
（_loadAll() async 导致预填有时没写入、点击有时不触发）——归因是错的，
那些现象是驱动自己造成的，不是 App 的。

#位置缺陷实测
1ts 过滤器（原 L333）[int]::TryParse 解析 epoch 毫秒。[int] 是 Int32，上限 2147483647，而当前 epoch 毫秒约 1.79 万亿 → 必然解析失败，$ts 保持 0 → 0 -lt $runStartedAtMs 恒真 → 每条记录都被当陈旧跳过[int]::TryParse('1794811097848') -> False, value=0；[int64]::TryParse(...) -> True
2Get-HistEntries 读文件（原 L190）Get-Content 不写 -Encoding UTF8，中文 Windows 上默认按 GBK(936) 解码 UTF-8 文件，误解码出的字符会破坏 JSON → 这些行计入 $bad 后被丢弃一条 135 行的真实历史：默认读法 91 好 / 44 坏，UTF8 读法 135 好 / 0 坏。丢掉的 44 行正是带中文错误文案的记录（invalid_args/tool_unavailable/exec_error）——即最该被验证的失败用例

两处都已修（[int64] + -Encoding UTF8），并用真机拉到的历史做过验证：135 条全部解析成功，
{"tool":"ping"} 与 {"tool":"info"} 均正确匹配到 status=ok 的新记录。
在此之前，该脚本从未产生过一次正确判定。

连带结论：fake-adb-test.ps1 那条 FAIL 不只固件 bug——即使固件修好，
Int32 溢出也会让它永远报 NOT RECORDED 而拿不到期望的 WRONG STATUS。
我先前「只是固件问题」的诊断不完整，是继续挖才浮出这两个的。

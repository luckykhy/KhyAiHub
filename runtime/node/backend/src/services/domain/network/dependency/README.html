dependency — Agent 依赖自愈子系统#

D2 业务上下文里的一个功能单元：当一次工具调用因为本机依赖缺失而失败时，
不把硬中断抛回用户，而是走「探测缺失 → 询问是否安装 → 隔离执行安装 → 回环重试」的交互式修复。

7 个源文件，全部有同名同目录的共置测试（node --test，192 例 / 0 fail，2026-09-29 复验）。

各文件的职责（取自各文件头注释，未做二次概括）#

文件角色
index.js单元门面，串起探测 → 询问 → 安装 → 重试
registry.js依赖缺失场景的单一真源：每个逻辑依赖收敛为四件事，禁止散落硬编码
resolver.js依赖探测、回溯辨认与安装计划构建
installRunner.js隔离执行依赖安装命令
installLocation.js决定 project 作用域依赖装到哪里（应对 backend 跑在只读目录的形态）
healingLoop.js自愈循环编排（核心流程）
toolchainVersions.js「按客户需求选版本」的工具链版本矩阵，纯叶子：零 IO、确定性、绝不抛

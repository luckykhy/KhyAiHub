1. 三问（规则 9 / PROCESS-010）#

问答
谁要的不是本轮任何人新提的需求——这 11 个源文件是既有跟踪代码（git status 里它们是干净的，本批一个字节都没改），出处是设计文档 [DESIGN-ARCH-036]，运行时唯一的生产接线点是 D1 侧 services/tool/toolUseLoopHelpers.js:1314-1339 的 maybeForgeStructuredIntent（observe 模式，默认开），第二个消费者是安全对抗侧 services/domain/security/adversarial/stressHarness.js:194-225 的 _driveFurnace。扇入实测 2 个文件 / 2 个 require 站点（判据：require 解析后落进本目录）。
为什么要这么做它想解决的是「一句自然语言里同时并存 3 个动作、模糊词、条件与反悔，下游模型只能临场猜」这个问题：把无序 NL 强制坍缩成三种机器可解析的形状（L0 ActionIntent / L1 TaskGraph DAG / L2 StateMachine），并按锁级（Prompt_Soft…Code_Hard…System_Block）给出该用多重的护栏。这一层的存在理由是省 token 与消歧义；它不买账的地方在于全部判据是词法表（VERB_MAP/VAGUE_RE/CONNECTORS/REVERSAL_RE），词表一漏就静默走轻锁——见 §4 与 khy.module.json 的 B31-F1/F2/F3/F18。<br>⚠ 「11 个源文件 / 扇入 2」是一个近孤岛：它没有测试网以外的真实负载，且目录内零 env、零 fs、零网络（全数清点，非抽样）。它到底是「该养的机制」还是「该退役的重量」，这是人的裁决，不是本 README 的裁决；本 README 只把事实摆清楚：生产侧确有 1 条默认开的接线（observe 模式），但该接线从不验封（assertForged 全仓只有 1 个调用者 = stressHarness，isForged 生产侧 0 个），所以熔炉的硬边界目前只在对抗测试里被行使。

2.4 熔炉数据模型（谁能读什么）#

ForgeEnvelope（封印信封） —— chaosInterceptor._forge（:124-141）的唯一产物形状：
{ [SEAL_BRAND]:true, sealed, seal, level, entropy, verdict, kind, payload, strategy,
degraded, writeLocked, entities, rawHash }，Object.freeze 浅冻结。
seal = HMAC-SHA256(SEAL_SALT, JSON.stringify(payload))，盐是进程私有 randomBytes
（:31）⇒ 信封跨进程不可验（重启后 assertForged 必抛「封印校验失败」）；
SEAL_BRAND 是 Symbol.for('khyos.structuredFurnace.sealed')（全局可达键）⇒
{ ...envelope } 浅拷贝仍然验封通过（B31-F4）。rawHash = sha1(text).slice(0,12)，
信封里不含原文——原文只以哈希形态存在。

三级 payload（envelope.payload，消费方只许读它，不许回碰原文——index.js:20 的约定）：

级别形状由谁产出由谁把关
L0 ActionIntent{kind,uid,action,target:{uid},params,confidence,strategy,entities}dimensionReducer.reducevalidateActionIntent（唯一校验 target.uid 是否落在 entities 里的层）
L1 TaskGraph{kind,uid,graph:{nodes[],edges[]},entities,confidence,strategy}intentWeaver.weavevalidateTaskGraph(payload,{hadDependency})（查节点 uid 去重、边端点，不查 node.target）
L2 StateMachine{kind,uid,machine:{initial,states[],transitions[],contradictions[]},entities,strategy,confidence,hasContradictions,contradictions}skeletonReconstructor.reconstructvalidateStateMachine（查 initial 与转移端点，不查状态 uid 去重）

FurnaceRejection（anomalyHandler.js:35-60）= 拒损异常，携带
{name,kind,missing[],conflicts[],detail,recoverable:false} 与 toJSON()；
它是熔炉对人类的唯一回问通道（observe 模式下被 gatedInput.furnaceRejection 记录）。
verdict 三值语义：PASS 原样返回 / DEGRADE 打标 degraded+sandbox+writeLocked
并把锁级 escalate 到 Code_Hard 起步 / REJECT 不返回而是抛出。

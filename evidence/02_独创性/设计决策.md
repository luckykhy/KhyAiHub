## 二、本仓自行设计的机制（每条给出规范真源，可点开读）

以下机制不是照搬某个开源项目的现成组件，而是本项目**自己定义并写成规范、再配执行器**的。
每条都列「它解决什么」与「机器在哪里强制」。

| # | 机制 | 解决什么问题 | 规范真源 | 执行器 |
|---|---|---|---|---|
| 1 | **三模态反馈契约**（修复=看病 / 新增=求学 / 删除=搓澡） | AI 报「已修好」但没人验证；改坏一片 | `[DESIGN-ARCH-113] AI修改三模态反馈契约-客户模式` | `scripts/ci/check-agent-feedback.js`（规则 5/6/7 = `RUNTIME-007/008/009`） |
| 2 | **规则遵守保障机制**（门成员资格从登记表派生，不在 CI 里硬编码） | 加了规则但门不跑；或门跑了规则已删 | `[DESIGN-ARCH-111] 规则遵守保障机制` | `scripts/ruleguard/` + `npm run rules:gate` / `rules:coverage` / `check:wiring` |
| 3 | **五通道决策矩阵**（状态直读 / 服务直调 / CLI / Web API / 看屏幕） | 一次操作该走哪条路全靠临场判断 | `[DESIGN-ARCH-071] 通道选择决策矩阵` | 规则层 + `check:gov-rules` |
| 4 | **委派边界第六通道**（默认自做，委派需过 G1/G2/G3 三闸门） | 把活随手甩给外部智能体，边界失控 | `[DESIGN-PROCESS-001] 委派边界决策矩阵` | `scripts/ci/check-delegation-boundary.js` |
| 5 | **新机制落地四阶段**（S1 观察者 → S2 顾问 → S3 门禁 → S4 主动修复，毕业看样本量不看时间） | 新写的检查器一上来就拦人，误报即瘫痪 | `[DESIGN-PROCESS-002] 新机制落地四阶段流程` | `scripts/ci/check-rollout-stage.js`（含「登记表 stage 必须等于执行器常量」的漂移检查） |
| 6 | **智能体工具授权矩阵**（默认拒绝；只读角色不得持 `Bash`；禁止 fail-open） | 提示词里说「你没权限」，机制上却照样能执行 | `[DESIGN-AGENT-002] 智能体工具授权矩阵` | `scripts/ci/check-agent-authz.js` |
| 7 | **仓库层级板块规范**（L0 `kernel`→L6 `tools` + 横切，依赖方向单向可查） | 目录自由生长，跨层引用无人拦 | `[DESIGN-LAY-005] 仓库层级板块规范` | `npm run check:layout` |
| 8 | **构建产物单一根**（可再生产物统一落 `entries/<producer>`，`.gitignore` 由登记表派生） | 构建垃圾散落根目录；忽略清单手写第二份必然漂移 | `[DESIGN-LAY-004]` | `npm run check:build-root` / `check:build-artifacts` |
| 9 | **三态目录立体分层 + 数据落点寻址表**（T0–T4 × 八领域） | 「这个文件该放哪」没有答案，根目录平铺到 211 项 | `[DESIGN-LAY-007] 三态目录立体分层方案` | `npm run check:data-layout`（`DATA-LOCATIONS.json`） |
| 10 | **可交付性基线 D1–D10**（度量必须有一根表针朝外：发布物是否真实存在） | 93 条规则全守内部自洽，0 条检查发布物存在 | `[DESIGN-DELIV-001]` + `[DESIGN-DELIV-002]` | `npm run check:delivery`（命令/别名/handler 三只棘轮） |
| 11 | **依赖来源原生**（构建与交付链路只走官方源；镜像须显式 opt-in） | 同一份 Dockerfile 在不同网络产出不同镜像，无人知晓 | `[DESIGN-DEP-001]` §10 + `[DESIGN-DEPLOY-001]` §3.3 | `scripts/ci/check-native-registry.js` |
| 12 | **软件著作权就绪规范**（判据=有没有人的意愿，四条硬线 C-M/C-X/C-E/C-MAT） | 「用没用 AI」被当成唯一标准，实际无从举证 | `[DESIGN-IP-001]` | `npm run check:copyright`（本目录即其产物） |

| 14 | **治理总纲十板块**（MOD/MEM/TOOL/ACP/API/BORROW/RUNTIME/PROCESS/SECURITY/DOCS） | 规则散落不可检索 | `[DESIGN-GOV-001] 治理总纲与可执行规则` | `scripts/ci/check-gov-rules.js` |
| 15 | **工具调用能力判定与文本拦截协议**（负向裁决要求正面证据） | 「回了文字没回 tool_calls」被误判成「不支持工具」，一次误判锁死该模型 | `[DESIGN-ARCH-138] 工具调用能力判定与文本拦截协议` | `services/backend/src/services/gateway/`（`toolCapabilityStore` 非对称继承） |

## 四、怎么追问这些决策

| 追问 | 打开哪里 |
|---|---|
| 为什么这么设计？ | 对应设计文档的「背景 / 备选方案 / 结论」段 |

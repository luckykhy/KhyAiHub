本目录 16 张 PNG 分四类，**全部由脚本生成或采集，无一张手工拼图**。

## 一之二、模块依赖图为什么算「实测」而不是手绘

`架构图/02_模块依赖图_实测.png` 的每个节点、每条边都来自 `collect-contribution.js` 第 6 段
对源码 specifier 的解析（`require()` / `import` / `export … from` / 动态 `import()`）：
相对路径按文件所在目录解析并补 `.js/.json/.vue/.ts/index.js` 落点，`@khy/*` 解析到
`platform/packages/*`，前端 `@/*` 解析到该应用 `src`；裸包名（npm 依赖）**不计为内部边**。
同目录内的引用算自环并剔除。

| 实测读数 | 含义 |
|---|---|
| 源文件 3,459 个 | 参与解析的代码范围（8 个统计根目录） |
| 内部可解析边 4,346 条 | 真实引用次数总和 |
| 目录节点 71 个 / 目录级边 257 条 | 图上的点与边（图取权重前 16 的节点） |
| 未解析 61 | 相对引用指向了不存在的落点——如实登记，不当 0 处理 |
| 外部 npm 包引用 4,076 处 | 与内部边分列，避免把第三方引用算成自己的架构 |

最强边 `backend:cli → backend:services` 1,103 次，可用
`grep -rhoE "require\('\.\./(services|utils|constants)/" services/backend/src/cli --include=*.js | wc -l`
做同向抽查（该 grep 只覆盖 `../` 一种写法，读数必然小于 1,103，方向一致即为通过）。

## 二、终端截图的可信度机制

`captureTerminals()` 的做法：`execFileSync(node, [bin/khy.js, ...args])` 捕获 stdout 原文，
只把 ANSI SGR 颜色翻译成 CSS，**不改写任何字符**；页面底部写明采集命令。
**唯一非产品自绘的元素是顶部那条标题栏**（`khy-os — <命令>`，由 `capture-runtime.js:147` 合成），
它不是产品窗口标识——递交前须知见 `../06_申报材料/递交核对表.md` §二 ⚠。

| 文件 | 命令 | 证明了什么 |
|---|---|---|
| `01_version.png` | `khy --version` | 软件可启动并自报版本 |
| `02_commands.png` | `khy commands` | CLI 命令面真实注册 |
| `03_hq_status.png` | `khy hq status` | 任务/Bug 台账可读，17 条 Bug + 29 条任务如实显示 |
| `04_storage_status.png` | `khy storage status` | 数据落点寻址可用 |
| `05_gateway_status.png` | `khy gateway status` | 多供应商通道面读数：一次输出列出 17 个已启用适配器（Kiro / Cursor / Trae / Claude / Codex / Ollama / 中转 / CLI…）与逐通道连通状态。名称改版（D-名2）后**不再是名称载体**，改作「AI 助手」一词的运行时佐证 |
| `06_trajectory_list.png` | `khy trajectory list` | **现行登记全称两个关键词的运行时读数**：同一张表里「条数」列 = 执行轨迹记录，「链」列的 `完整(n)` = `verifyTraceChain()` 的链路校验结论（三态：无链 / 完整(n) / 断链@#n）。`khy trace list` 渲染同一张表，实测逐行相同 |

第 1–4 条与第 6 条是只读离线命令；第 5 条 `gateway status` **会对外探测**已启用通道的连通性
（实测打印「并行探测 7/17 个已启用通道（上限 22s）」），且部分通道的探测会触发一次最小模型调用
——同一张截图底部能看到「已收到模型响应」字样。**因此本底档不宣称该采集零成本**，
只如实标注可能产生少量费用。`运行截图清单.json` 里该条带 `对外探测: true`。

> ⚠ **`06_trajectory_list.png` 递交前需人工过目**：「在做什么」列是**用户真实输入原文**
> （含第三方品牌名与私人事务性提问），非演示数据。采集器按「不改写任何字符」的纪律
> 不做脱敏——脱敏即改图，与「截图不得有剪切/PS 痕迹」冲突。若要作登记材料，
> 正确做法是**在干净数据目录下跑同一命令重拍**，而不是编辑本图。

## 三、界面截图为什么**暂不可**作登记材料（两条硬伤，如实写）

1. **界面标题与登记全称不一致。** 登记全称现行值（D-名2，真源 `[MGMT-OTHER-006]` §一）为
   《基于执行轨迹记录与链路校验技术的AI助手平台》，版本号另栏填 `V1.2.0`（沿用仓库 G1 现值），
   而实测浏览器内标题仍是：
   - `apps/ai-frontend` → `登录 · KHY AI 管理平台`
   - `apps/khyos-desktop` → `KhyOS Desktop`
   「界面名称与申请表软件全称不一致」是实务高频补正点，改名（阶段 2）后必须重拍。
2. **未连接后端。** 本组截图是本地静态托管构建产物渲染的结果：
   ai-frontend 停在登录页（无凭据），桌面端显示的是前端内置演示会话、状态栏为「未连接」。
   这类画面能证明「界面存在且能渲染」，不能证明功能闭环。

**非空白保证**：界面截图走 CDP 渲染，采集器轮询 `document.body.innerText` 长度与元素数，
实测到 ≥20 字符且 >30 个元素才截图；不满足则**该条不会生成**（宁可缺，不交空白图）。
每张的实测读数记在 `运行截图清单.json` 的 `渲染后元素数` / `渲染后可见文本长度` / `可见文本抽样`。

## 五、图片完整性

- 尺寸统一 1500×1000（`--window-size` / CDP `Emulation.setDeviceMetricsOverride`）
- 每张在清单里带 `字节` 与 `sha256`；`npm run check:copyright` 会对 0 字节图片判 **error**
- **本节四类分类标准有执行器**：`check-copyright-readiness.js` 逐类查 `图表/ 界面截图/ 架构图/ 终端截图/`
  是否各有非 0 字节图片，缺类报 `copyright-evidence-image-kinds`（S1 阶段降级 warning，不拦截）。
  此前只有文档声明、无守卫兜底，属「声明面有标准、执行面不查」的缺口，现已补上
- `../05_索引与对账/证据总清单.json` 逐文件登记路径/字节/sha256/行数（PNG 另记宽高），
  改过一个字节就会被对出来

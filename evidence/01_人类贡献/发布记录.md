## 三、CHANGELOG 段落（版本段推导的依据）

```bash
grep -n '^## ' CHANGELOG.md
```

| 段 | 位置 | 类型 |
|---|---|---|
| `1.2.0` | CHANGELOG.md:8 | `### Fixed` + `### Added` → MINOR |
| `1.1.14` | :53 | 修复段 |
| `1.1.12` | :118 | 修复段 |
| `1.1.9` | :139 | 修复段 |
| `1.1.8` | :241 | 修复段 |

本仓的版本段是**可机判**的：`### Added` → MINOR，`### Changed/Removed/Security` → MAJOR/MINOR，
仅 `### Fixed` → PATCH（`[DESIGN-SEMVER-002]`）。先写 CHANGELOG 段、再 bump 版本号，
由 `changelog-new.js --check` 以 `pyproject.toml` 为锚校验。

## 四、发布链路（谁自动、谁人工）

| 环节 | 触发 | 是否人工点头 |
|---|---|---|
| 写 CHANGELOG 段 → bump 三源版本号 | 人决定发版 | ✅ 人 |
| 推 `main` | 人执行 commit/push（红线 R1 禁止 AI 自动提交） | ✅ 人 |
| 推 `vX.Y.Z` tag | 人执行 | ✅ 人（**唯一一次点头**） |
| tag 之后：测试→版本校验→release-gate→构建→签名→SBOM→发包→Release 资产 | CI 自动 | ❌ 不再人工 |
| Gitee 镜像同步 | 推 main / tag 自动 | ❌ |

四条硬阻断（`check-version-sync`、`changelog-new --check`、`release-gate.js`、tag 与 `pyproject.toml` 相等）
**禁止改成 `continue-on-error`**。完整规则见 `AGENTS.md`「何时 bump、推哪里、什么自动触发」与 `[DESIGN-SEMVER-002]`。

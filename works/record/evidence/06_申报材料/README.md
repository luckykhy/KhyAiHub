## 三、生成规程（顺序不可颠倒；工具已在仓外就位，不重写一遍）

1. **定字段真源**：改 `软著交付/Khy-OS/06_工具/registration.json` 三值，
   取值抄本夹 `递交核对表.md` §一。
2. **实拍截图**，逐张记命令，落 `截图/`。主证据是 `khy trajectory list`
   （一张图同时证「执行轨迹记录」与「链路校验」两词，`完整(54)` 由 `verifyTraceChain()` 算出）。
   **禁用 `khy history`**——实测返回「暂无保存的对话记录」，空表截图等于没有证据。
   界面截图前须先解决界面标题与登记全称不一致（核对表 §三第 4 项），否则这一整步作废。
3. **抽源程序 60 页**（仓外 `06_工具/`）：`extract_code.py` 选材 → `calibrate_final.py` 校准
   → `verify_material.py --name "<全称>" --version "<登记版本>"` 一条命令同时完成
   重渲染两端 md（换页眉）+ 生成 PDF + 逐页核验（页数 / 每页页眉 / 每页 ≥50 行）。
   **实测已冻结的事实**：换页眉**不改变页数**——HTML 里是恰好 30 个 `.page` 块，
   每块 55 行代码 + 1 行页眉，`1649 + 1 = 1650 = 30 × 55`，不需重新校准选材。
   产物落本夹 `源程序/`。
   > ⚠ **现有选材与新名称不匹配，须先定案**，见核对表 §五。
4. **写说明书**，落 `说明文档/`：硬件环境 / 软件环境 / 编程语言 / 源程序量四项按实际填，
   主要功能一节对应「执行轨迹记录与链路校验」；某模块若无截图，正文保留可见文字
   `【截图预留：模块名】`，**不得用 HTML 注释**（Word 里看不见，会被当成漏了）。
5. **对账**：更新 `递交核对表.md` 的逐件状态，再跑本仓守卫，不许凭印象说齐了。

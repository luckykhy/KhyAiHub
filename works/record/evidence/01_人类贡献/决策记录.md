## D-软著skill ｜ 2026-09-29 ｜ 软著材料生成器以 vendored 方式入仓，约束载体是 AGENTS.md 规则 9

**人的原话（需求来源，C-E1 的「谁要的」）**：
> 「https://github.com/luckykhy/SoftwareCopyright-Skill ，希望以后Khyos的代码都能结合这个skill，为申请软件著作权而努力，不是装到 ZCode,而是把这套 skill 变成 Khy OS 仓库的约束，让任何来改代码的智能体(读 AGENTS.md 的 Claude Code / Codex / Cursor / Kiro / ZCode)都必须遵守」

**为什么不是「装进某个智能体」**：本仓的约束入口从来是 `AGENTS.md`（规则 9 = `PROCESS-010`），
装进单一 agent 的插件目录只对本机某一个工具生效，新克隆机器与其它智能体拿不到 ——
与「任何来改代码的智能体都必须遵守」这句话直接矛盾。故落点必须是**随 git 分发的仓内文件**。

**落点为什么不是 L6 `tools/`（AI 自曝假设，D-界1 同款纪律）**：
层级判据上它是 L6 形态（开发期手动调用、不参与运行时），初选即 `tools/software-copyright/`。
实测否决：`.gitignore:184` 忽略 `tools/deepseek-eyes/`，`git ls-files tools` = **0 个跟踪文件**；
埋在那里 = 约束在新克隆机器上不存在，违反多机自举与 `[DESIGN-DELIV-001]` D3。
改落 `scripts/copyright/`（`[DESIGN-LAY-005]` §1.2 工程横切层，与既有 `scripts/evidence/` 同族，随 git 分发）。

# [DESIGN-LAY-010] 目录结构唯一原则：位置与语义双射

> **原则 · 「什么算好的目录结构」的唯一判据** · 先用一句话回答「好的结构长什么样」，再给一条可双向验证的测试，最后列本仓实测证物与落地动作。
>
> **定位（必读，防重叠）**：本篇**不登记任何目录、不复制任何名册**。目录清单与依赖方向的真源仍是 `[DESIGN-LAY-005]`（层级名册）、`[DESIGN-LAY-002]`（层内可见性）、`[DESIGN-LAY-004]`（产物落点）、`[DESIGN-LAY-009]`（数据 SSOT）。本篇管的是这些规范共同服务的**那个判据**：凭什么说一棵树是好的。按 `[MGMT-STD-008]` §2.2「重叠即违规」，本篇只出判据，名册一律指回上述四篇。
>
> **效力**：无规则 ID、无守卫（规则 12 的棘轮：规则数只降不升，新增一条须先退役一条）。它约束**评审时的判断**，不进提交流程。
>
> **谁该读**：设计新目录、评审目录迁移、被问「这个文件放哪」的人与 AI。

## 一、原则

**位置 = f(语义)，f 必须存在、单射，且 f⁻¹ 只用目录名就能执行。**

口号版——同一映射的三个面：

> 一个字节只有一个家；一个家只有一个理由；只看名字就懂这个理由。

| 双射的要求 | 失效叫什么 | 现场症状 |
| --- | --- | --- |
| **存在性**：任何内容都有家 | 无家可归 | 临时物 / 生成物落根上，与真层并列 |
| **唯一性**：只有一个家、一个理由 | 别名 / 混家 / 上帝目录 | 同一内容两条可写路径；一个目录两个职责 |
| **可读性**：理由只读名字就懂 | 名字不表意 | 需要注释解释「这目录为什么在根上」 |

前两行是逻辑，第三行是视觉。**它们不是两套标准**——视觉是 f⁻¹ 的可执行性，逻辑是 f 的单射性，同一个映射的正反两向。

## 二、唯一测试

给一个没看过代码的人，两向各做一次，**两次试错以内命中即为合格**：

| 方向 | 怎么问 | 测的是 |
| --- | --- | --- |
| 反向（视觉） | 只给 `tree -L 2`：「要改 X，动哪些目录？」 | f⁻¹ 能否只靠名字走通 |
| 正向（逻辑） | 随机指一个目录：「什么变更会落到这里？」 | f 是否单射；答案出现「和」即破裂 |

只做通一向的仓库是半瘫的。常见形态是正向基本通（有真源意识）、反向靠人传人——那正是「治理很重、新人五分钟找不到地方」的成因。

## 三、机械推论：同层同轴

**每一层的兄弟节点必须共享同一个分类轴。** 位置是坐标，第 n 位是第 n 层轴的一个取值；同层混两个轴，这一位就不可判定（「这层是按技术栈分还是按产品分？」答不出 = 只看名字算不出位置）。

视觉规则不必另立，全部是它的 fallout：

| 视觉特征 | 为什么必然成立 |
| --- | --- |
| 一眼可数 | 一个轴的取值集合有限、可枚举 |
| 平行命名 | 同轴取值用同一语法 |
| 深度均匀 | 轴每下移一层才切换一次 |
| 无杂物 | 临时物没有语义，拿不到坐标 |
| 不写序号前缀 | `01_` 是排序意图（呈现轴），不是语义；重排即全树改名 |

## 四、轴的选择：第一层必须是「变更原因」

双射不替你决定各层选什么轴。只规定一条：

**顶层轴必须是「引起变化的原因」（业务域 / 变更源），不是技术栈。**

顶层按 `runtime/`、`delivery/`、`apps/` 切，等于用「用什么写」当坐标第一位；而变更的语义第一位是「为什么变」。后果是一个需求的 diff 撒满全仓。

## 五、本仓实测证物（2026-11-18）

1. **唯一性破裂（最重）**：根 `khy-Trajectory/` 与 `runtime/khy-Trajectory/` 都是 junction，均指向 `works/data/khy`（各 246 项）。一份内容两个家，还分属两层；名字像代码层，实际是数据主目录别名。写入方从任一路径出发都「看起来对」。

2. **同层混轴**：`docs/` 下 `01_INIT_立项` … `19_资产` 是文档类型轴，`html/` 是生成物落点（`scripts/docs/build_docs_site.js` 产出），`tui-interaction-optimize/` 是一个工作项——三个轴并列。`html/` 的位置必须靠「落点由 `htmlRelFor` 单一定义」的说明交代，而不能靠位置自解释。**需要解释，就是 f⁻¹ 走不通的物证。**

3. **同层混轴 + 层粒度不一致**：`delivery/` 下 `channel` / `extension` 是层级轴（`scripts/ci/check-repo-layout.js` 的 `LAYERS` 里 L4 / L5），`web` / `mobile` / `market` / `brand` 是形态 / 资产轴，守卫名册只登记前两个，其余被吞进粗粒度的 `delivery`＝D4。同层兄弟不同轴时，按目录前缀判层这件事自身失效。

4. **命名不平行**：`runtime/` 下 `boot` / `node` / `substrate` 与 `khy-Trajectory` 同层，PascalCase 混在小写单词里。**视觉上「多出来的那个」与逻辑上「不属于这个轴的那个」是同一个东西**——一条正则盖不住全部兄弟，即有异物。这是最便宜的轴污染检测器。

5. **存在性失败**：根上 `$TEMP`、`%EV%`、`-p`、`cd`、`done`、`echo`、`mkdir`（shell 引号事故残留，2026-11-13～18）+ 80 个 `.tmp-*` 残留 + 14 个 diff 文本。没有语义 ⇒ 拿不到坐标 ⇒ 只能落根上，与真层并列。

## 六、落地动作（守卫若开工，判据按此写）

1. **目录名册 = 轴名册**：每个目录断言它在第 n 层轴上取哪个值；同层语法一致性用一条正则覆盖全部兄弟；新增取值须改名册。
2. **禁别名（含 junction / symlink / 硬链接，2026-11-18 用户裁决）**：每份内容只有一个可写路径，且这个路径必须是**磁盘上真实的目录项**——链接把「家」变成指路牌，`dir`/`tree` 看到的东西和磁盘上真实存在的东西不一致，视觉层就开始说谎。兼容需求只能走「生成 + 登记」（`DATA-SSOT.json`），不得以真源身份出现在层级名册里。
3. **用 f 判据替换体积判据**：断言「位置可算」比断言「全部源文件带生命周期清单」便宜得多，也更贴根因——位置能算出来，才谈得上往里塞东西。

## 七、验收

**把 `scripts/ci/check-repo-layout.js` 里 `CROSSCUTTING` 的解释性注释删掉，树还读得懂吗？**

读不懂，说明位置 ⟺ 语义是靠注释与人传人撑着的，不是靠结构本身——那就是「结构还没做好」的定义。

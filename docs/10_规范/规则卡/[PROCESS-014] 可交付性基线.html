约束#

D1–D10 十条判据 + 任务面棘轮 + 渠道 CI 完备性，由 scripts/ci/check-delivery-baseline.js 机械执行，阈值与任务面基线全部来自 [DESIGN-DELIV-002] §4 的 $schema=khy-delivery-surface/1 JSON 块（阈值外部化，不得硬编码在检查器内部）。D1 仓库完整性：git fsck 的 missing blob / missing tree / missing commit / broken link / cache-table 失效计数全为 0，且 git log --oneline --all 退出码为 0。D2 发布物：dist/ 内 wheel 与 sdist 均存在且非零字节。D3 克隆零缺件：git status --porcelain 的 ?? 与 D 计数均为 0。D4 失败阻断：发布相关文件里，行内同时命中「校验类词（sign/verify/checksum/audit/sbom）」与「吞错词（|| echo/|| true/continue-on-error: true）」的计数为 0（注释行不参与判定）。D5 校验和：必须存在生成点，且同一文件内可见其被发布出去的回路，否则判「生成但无回路」。D6 SBOM：必须存在生成点，且同一条 workflow 内存在消费步骤（grype / osv-scanner / trivy / anchore / cyclonedx validate），只 upload-artifact 判不合格。D7 债务棘轮：复用既有 scripts/ci/check-debt-ledger.js（退出码 0 为通过），不新建机制。D8 阶段结算：与发布门相关的机制不得在 S1/S2 停留超过 s1MaxDays（默认 90 天），逾期即不合格。D9 黄金路径：必须存在 scripts/ci/check-golden-path.js 且被 releaseGateStages.js 引用。D10 边界：边界文档必须存在且含「不支持清单」。棘轮：命令 / 别名 / handler / 规则条目四项实测值不得超过 §4 登记的基线（只降不升），且重测口径必须与基线登记的方法一致。渠道：声明的每个交付渠道要么有 ciWorkflow，要么已在边界文档声明为不承诺交付。检查器不得在阈值真源缺失时退回内置默认值 —— 删除真源必须报 delivery-thresholds-missing，使读数失去意义而非静默继续。

授予权力#

授权用一条命令取得可交付性的全量读数（npm run check:delivery）与机读结果（--json，供测试与看板消费）；授权在 CI / 发版前以 recommend 档运行它，把「能不能交出去」从评审意见变成可回归的数字；授权维护者冻结命令面（棘轮只降不升）——即有权拒绝「再加一个命令」而不必逐个论证该命令无用，只需指出棘轮已满；授权在退役命令后下调基线，从而把「一进一出」变成可操作的动作而非口号；授权按 [DESIGN-DELIV-002] §5.2 的既定路径升阶到阻断档（改执行器 STAGE 常量 + 登记表 severity + 发布门该阶段 tier，回退为反向改回）。判据不满足时不再持有「以内部一致性通过来替代交付物存在」的余地，但持有「声明豁免并写复核到期日」的权力。

提供福利#

把「交付」从一个无法反驳也无法验证的感受，变成一个可跑、可机读、可回归的记分板。实测起点（2026-09-24）：dist/ 不存在（可安装包从未在本机产出过）、发布链上 2 处 sigstore 签名失败被 || echo 吞掉、SBOM 只 upload-artifact 无任何消费者、无黄金路径检查、仓库根躺着 4 个 shell 重定向事故文件。这些没有一个会让既有守卫变红 —— 93 条规则守的是仓库内部自洽，75 个 check-* 里 0 个检查「产物是否存在」。本规则给出的是第一个指向外部的表针，并同时给出任务面的封闭边界，使「完全不支持的任务」（如 Windows arm64、真实下单、无 CI 的三条渠道）被写明而非留白。

例外#

两类：① 与单次提交无关的全仓状态读数（D1 仓库完整性 / D2 发布物 / D3 克隆零缺件 / D7 债务棘轮）在 --changed 下不报 —— 一个 pre-commit 钩子不应要求本机存在发布产物；但任务面棘轮恒报，因为命令数与规则数正是提交动作直接改变的。② 声明「本仓不做签名」并移除相应步骤，是合法的收敛方向（D4 判的是「失败被吞掉」，不是「必须有签名」）—— 移除优于吞掉。阶段豁免：本条按 [DESIGN-PROCESS-002] / PROCESS-008 落地为 S1 观察者（gate=commit 会跑 + severity=advisory 只记录），[DESIGN-DELIV-001] §4.3 关于「D1/D4/D7 可直进 S3」的主张未自动采纳，需一次显式人工裁决。

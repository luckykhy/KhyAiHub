## 一、要解决的问题：仓库里没有任何东西能回答「谁先谁后」

本仓 991 份文档里只有 **127 份**带 `<!-- IMPL-STATUS: ... -->` 标记，
而**没有任何脚本消费该标记**（grep 全 `scripts/` 零命中）。也就是说
「这份设计落码了没有」从来只是一句人工约定，没有任何东西会因它说错而报警。

它已经说错了，且不是个别：

| 文档 | 标记 | 实情 |
|------|------|------|
| `[DESIGN-ARCH-131]` | 首行 `done` | 同一文件第 4 行写「设计提案（未落地）」，第 597 行写「本文档为设计提案，未落地任何代码」；三棵代码树 grep 0 命中 |
| `[DESIGN-ARCH-030]` | `done` | 整套实现（`self_healer.js`、`build.sh`、16 例测试、`ProgressRenderer`）已从仓库消失 |
| `[DESIGN-ARCH-001]~[049]` | 42 篇中 35 篇 `done` | 该标记与实际漂移严重脱节，把 `done` 当可信信号会踩上面几条 |

**判据不是「有没有用 AI」，是「标记与代码是否一致」。** 本规范只解决这一件事。

## 二、硬线：标记必须与实现一致

> **一份文档标 `IMPL-STATUS: done`，它声称的实现路径就必须在仓库中真实存在。**
> 标 `todo` 的文档可以写尚不存在的路径——那是规划，不是漂移。

违反者由 `check-doc-drift.js` 报 `impl-status-done-but-missing`。

**为什么单独立这条**：本仓此前 93 条规则全部守「仓库内部自洽」，
没有一条检查「文档声称的东西是否还在」。一个恒被治理的内部 + 一个从不被测量的外部，
正是「治理通过率高但文档不可信」的结构性成因。

## 二之一、适用范围：标记只对「提出设计/规范并声称落码」的文档有意义

`IMPL-STATUS` 回答的是「这份设计落码了没有」。对**索引页、修仙学AI 叙事章节、
事后报告、立项/概念科普**这类文档，这个问题**本身不成立**——它们不描述实现。
给它们硬塞 `done`/`todo` 只会制造几百条虚假声明，且这些声明永远无人复核。

故守卫按板块声明适用范围（实测 993 份 md）：

| 分类 | 份数 | 处理 |
|------|------|------|
| **适用**：`03_DESIGN_设计/` + `10_规范/`，去掉 `00_INDEX_*` 与规则卡 | 329 | 必须标注，参与漂移判定 |
| **不适用**：`00_INDEX_*` 索引页（即便在适用板块内） | 20 | 不要求、也不判 |
| **不适用**：规则卡（`docs:rules-cards` 从登记表生成的渲染产物） | 97 | 不要求、也不判 |
| **不适用**：报告 / 修仙学AI / 立项科普 / 素材 | 547 | 不要求、也不判 |

「不适用」不是免责，而是**明确写下这件事无需标记**，好过留一个
「不知道它算不算」的模糊地带。若日后某类文档（如运维手册）开始声称落码，
再按同一判据纳入适用范围即可。

范围内未标注者单列 `impl-status-missing-in-scope`——**缺标记不是错，是账未清**，
故不并入漂移 finding，只作为待补清单暴露。

## 三、判据：锚定路径存在性（信号 A）

从文档反引号里抽出**根锚定**路径，逐条判其在仓库中是否存在。
搬迁过路径的，先过 2026-10-05 方案 P 的 7 组前缀映射，再退到同名兜底
（只在 `scripts/` `entries/` `works/` 子树内找，且必须**唯一命中**）。

**实测（2026-10-18 首轮）**：991 份 md、352 条候选路径，映射后仍缺失 **61 条**；
其中标 `done` 的 **54 条**、标 `todo` 的 **7 条**。
`done` 与 `todo` 的这个不对称就是它有区分力的证据——
若两者相当，则标记不携带信息，本守卫无意义。

### 3.0 三个状态值

| 状态 | 含义 | 路径缺失是否算漂移 |
|------|------|-----------------|
| `done` | 设计已落码，正文所列实现路径应当存在 | **算** —— 这正是本守卫抓的东西 |
| `todo` | 尚未落码（调研 / 提案 / 规划） | 不算：写尚不存在的路径是规划本身 |
| `superseded` | 曾落码，实现已不在仓库；文档保留为设计记录 | 不算，但单列 `impl-status-superseded-historical` 供审计追溯 |

`superseded` 是 2026-10-18 收口时新增的第三态：它让「实现曾存在但已被删」
与「本就没实现」不再共用一个 `todo`，从而**保住 `done` 归零这个可判定的收口信号**。

### 3.1 显式排除的误报来源

| 排除项 | 理由 |
|--------|------|
| `.khy` / `.khyos` / `.zcode` / `.claude` / `node_modules` | agent 基础设施与本机态；`.khy`/`.khyos` 按 `[DESIGN-LAY-007]` 是 gitignore 的非交付面 |
| 含空格 / `*` / Windows 反斜杠的 token | 不是可核验的仓内路径 |
| **命名模板**：`<域>.js`、`{ToolLines,ProcessGroup}.js`、`...` | 给读者看的占位写法，判它存在永远是假的 |
| `docs/html/` | md 的孪生构建产物，同一内容会双报 |
| 相对片段（`src/cli/router.js`、`failsafe/errorCodes.js`） | 无根锚点，判不出它指向谁 |
| 同名兜底命中多处 | 判不出来，不算 finding |

### 3.2 三条必须写在代码里的判据细节

它们各自都造成过**假阴性**，即漏掉本守卫最该抓的那类漂移，
且都是靠拿已确证的样本反查才发现的：

1. **搬迁映射必须落到真实存在的文件**，不能只判前缀目录存在。
   否则 `packaging/self-heal/build.sh` 会因 `packaging/` 已整体搬到 `works/ship/`
   而被判为「已搬迁、存在」，而那份实现其实**在搬迁中丢了**。
2. **锚定判定必须在搬迁映射之后**，不能放在前面。
   `packaging/` 早已不在仓库根，先锚定会把它当相对片段直接丢掉。
3. **同名兜底必须覆盖 `runtime/` `delivery/` `apps/`**，不能只搜
   `scripts/` `entries/` `works/`。domain 化把 `src/services/X.js` 拆到了
   `src/services/domain/<域>/X.js`——实测 10 条（`budgetExecutor.js`、
   `distiller.js`、`sidebarRail.js`、`ccMcpBridge.js` 等）正是这样被误判成
   「实现消失」，而它们的实现其实都在。

第三条同时把守卫的运行时间从 14s 降到 <1s（一次扫描建索引，供全批复用）。

## 四、为什么不用 git 时间戳判先后

第一版设计的主信号是「同一 commit 改了代码却没改文档」。**实测证伪**：

```
both=12  codeOnly=41  docOnly=99  neither=148
41 笔 codeOnly 里 33 笔（80%）在随后 5 笔内就补上了文档提交
```

即该守卫的主要命中对象**正是本仓明文规定的工作流本身**
（先提交代码、另起一笔落账补文档，见 `[DESIGN-PROCESS-001]`）。
一个把仓库既定约定当主要输出的守卫，唯一教会人的事就是忽略它。

另有三条机械死因，任一条都能让信号恒空：

- `pre-commit` 时 commit 尚不存在，必须 `--cached`；
- merge commit 上 `git diff-tree` 静默返回空，而 CI 的 `pull_request`
  checkout 落在 `refs/pull/N/merge`；
- 本仓对象库 `fsck` 有洞（22 条 missing，8 个分支推不出去）。

**故 v1 不使用任何依赖 git 历史的信号。** 判据改为纯文件系统操作，
对上述三类故障全部免疫，全仓扫描 <15s。

## 五、落地阶段与升阶

`STAGE = 'S1'`：**观察者，只记录不阻断，恒 exit 0**。
这是 `[DESIGN-PROCESS-002]`（`PROCESS-006`）四阶段制的第一阶，
**不得直接进门禁档**（PP-1）。

**升阶是人的决定，不是脚本的决定。** 一次只升一阶（PP-6），须同时改三处：

| # | 位置 |
|---|------|
| 1 | `scripts/ci/check-doc-drift.js` 的 `STAGE` 常量 |
| 2 | `RULES-REGISTRY.json` 中 `DOCS-005` 的 `severity` |
| 3 | `FEATURE-OWNERSHIP.json` 中 `doc-drift-guard` 的 `stage` |

毕业看**样本量不看时间**：S1→S2 需 ≥200 条样本且无解释不了的样本；
S2→S3 需 ≥50 条提示后误报率 <10%；S3→S4 需 ≥20 次真实拦截且豁免率 <20%。

> ⚠ **`severity` 必须显式写 `advisory`**。`check-rollout-stage.js:197` 的 PP-3
> 会**复算** ruleguard 的 `gateStrength()`，未声明 severity 时 P1 会**派生**成
> blocking 而报 error。「没写 severity」与「写了 advisory」字面完全不同、效果可能一样。

**S1 期间请勿据本守卫批量改文档**：它有约 10% 已知误报（§3.1），
且 864 份无标记文档完全不在其视野内。它的用途是**给出候选清单供人工判断**，
不是自动裁决。

## 七、首轮收口结果（2026-10-18）

首轮 61 条缺失按「能不能机械修」分四类，逐类处置：

| 类 | 条数 | 处置 | 依据 |
|----|------|------|------|
| 误报：命名模板 / `node_modules` | 7 | 改守卫排除 | `<域>.js` 是占位写法，判它存在永远为假 |
| 路径已迁，仓内唯一同名 | 6 | 改文档指向真身 | `archDebtScan.js` → `runtime/node/backend/scripts/` 等 |
| domain 化后路径变更 | 10 | 改守卫同名兜底覆盖面 | 实现其实都在 `domain/<域>/` 下 |
| 实现确实不在仓库 | 38 | 据实改标记 + 写明原因 | 见下 |

最后一类又分两种，**改法不同**：

- **`todo`（2 份）**：文档自述就是「调研 / 提案 / 借鉴清单 / 未实施任何代码改动」，
  原 `done` 是误标 → 改 `todo`。
- **`superseded`（10 份）**：文档自称已实现、实现却不在仓库 → 改 `superseded`，
  文档保留为设计记录，并在正文补「标记校正 + 原因」。

**终态**：`done` 类缺失 **0 条**；`superseded` 26 处历史路径（预期，单列可查）；
`todo` 12 处真规划。

**这一轮改动本身的可信度检验**：每一步都用已确证的样本反查过——
`[DESIGN-ARCH-030]`（写 `done` 而实现已消失）现在被正确判为 `superseded`，
`[DESIGN-ARCH-105]`（自述「未实施任何代码改动」却标 `done`）被判为 `todo`。

## 八、覆盖面与其局限（不夸大）

第二轮补标后（2026-10-18）：

| 覆盖 | 不覆盖 |
|------|--------|
| 适用范围内 **329 份文档 100% 已标注**，其中 `done` 类漂移 **0** | **664 份范围外文档**（索引页 / 规则卡 / 报告 / 叙事 / 科普）——按 §二之一明确判定为不适用 |
| 路径级漂移（实现消失、路径搬迁） | **内容级漂移**：数值、口径、命令、错误码与代码不符 |
| 方向一：文档声称的没有 | 方向二：代码更新了但文档没跟上（需人工判定，git 不可用见 §四） |
| 三种状态（`done` / `todo` / `superseded`）分别独立报告 | 296 份保守标 `todo` 的文档，其真实状态**仍需人工复核**——批量补标只保证「不撒谎」，不保证「判对了」 |

**一句话**：本守卫把「标 done 但实现已消失」这一类变成可见并已收口归零，
**不等于**解决了全部漂移。补标的 296 份 `todo` 是**待复核的账**，不是已完成的判定。

### 8.1 批量补标的判据（可复核，非猜测）

对范围内未标注的文档，只用可核验的证据落标记，每份都在正文写明依据：

| 判据 | 落状态 | 份数 |
|------|--------|------|
| 路径主张全部可解析 **且** 文中自述「已实现/已落地/实现完成」 | `done` | 3 |
| 路径主张部分失效 **且** 自述已实现 | `superseded` | 0 |
| 其余（无自述实现 / 自述为调研提案 / 无任何路径主张） | `todo`（保守） | 296 |
| `00_INDEX_*` 索引页 | 不标（不适用） | 20 |

只有 3 份被判 `done`，是因为判据要求**路径证据与自述同时成立**——
多数老文档自述缺失或自相矛盾，一律保守落 `todo`。
**宁可 296 份待复核，也不要 296 份虚假声明。**

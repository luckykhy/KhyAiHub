## 一、第三次订正一个判断

本仓此前两次就「数值漂移能否机检」下过判断，两次都错：

| 版本 | 判断 | 实测结果 |
|------|------|---------|
| 初版 | 「数值、口径、命令与代码不符无法机械判定」 | 对**绝大多数**数字成立 |
| 二版 | 「内容级漂移不在射程」 | 被 DOCS-006 推翻（端点字面量可逐字比对） |
| 本条 | —— | **对「同名常量」这一类成立** |

**推翻的推理**：文档写下 `<常量名> = <值>` 时，文档与代码说的是**同一个名字**——
这给了机器一个可逐字比对的锚点。文档写 `MAX_GATES = 227`、代码写
`const MAX_GATES = 237`，两者指的是同一个东西，无需任何启发式推断。

## 二、判据（两条，都不执行任何命令）

| # | 判据 | 说明 |
|---|------|------|
| N1 | **常量值**：文档写 `<常量名> = <值>`，代码里该常量有唯一确定的值 | 两者不符即漂移 |
| N2 | **行号**：文档写 `file.js:41 MAX_GATES = ...`，而该常量实际在第 50 行 | 引用的行号已失效 |

### 2.1 实测（2026-10-19）

330 份适用范围内文档，**83 处**「常量名 = 数值」主张，其中 **43 处可判定**
（代码里同名常量的值唯一），**10 处不符——10/10 人工核实为真漂移**：

| 文档 | 文档称 | 代码真值 | 行号 |
|------|--------|---------|------|
| `[DESIGN-ARCH-132]` | `MAX_GATES = 220` | `237` | 称 `:32`，实为 `:50` |
| `[DESIGN-ARCH-133]` | `MAX_GATES = 220` | `237` | 称 `:32`，实为 `:50` |
| `[DESIGN-ARCH-134]` | `MAX_GATES = 220` | `237` | 称 `:32`，实为 `:50` |
| `[DESIGN-ARCH-135]` | `MAX_GATES = 220` | `237` | 称 `:32`，实为 `:50` |
| `[DESIGN-ARCH-136]` | `MAX_GATES = 220` | `237` | 称 `:32`，实为 `:50` |
| `[DESIGN-ARCH-137]` | `MAX_GATES = 220` | `237` | 称 `:32`，实为 `:50` |

「R1=9、R3=4、exit 1」同类的漂移，只不过那次漂的是运行读数，
这次漂的是**源码里的常量**。

## 三、修复时为什么改「行号」而不是「追行号」

`[DESIGN-DOC-004]` 之外的 `[DESIGN-DOC-003]`（README 内容规范）与
`RULES-REGISTRY` 的 DOCS-004 都已写明：

> 引用代码与文档位置一律给符号名或小节标题，**不得给行号**
> （行号是最易漂移的副本）

所以修法不是把 `:32` 追成 `:50`——下次在文件前部插一行又失效——
而是**去掉行号，只留符号名**：`check-tui-gates.js` 的 `MAX_GATES = 237`。

**这条守卫同时在守 DOCS-004 的约束**：它把「文档引了失效行号」变成可判定。

## 四、刻意不做的三件事

### 4.1 不执行文档里的任何命令

文档写 `node scripts/foo.js` 就跑它，等于**让一份文档获得执行权**——
那不是校验，是攻击面。需重跑才能得到的读数（如 `archDebtScan` 的 R1/R3、
`check-tui-gates` 的 token 计数）须由**白名单注册表**显式登记后才可跑，
不在本条射程。

本条只做**读文件 + 逐字比对**，不 spawn 任何进程。

### 4.2 同名多值不判

代码里 `MAX_GATES` 若在两处定义为不同值，说明它有上下文差异
（配置 vs 默认值），机器判不出——**跳过而不是猜**。

### 4.3 纯叙述性数字不判

「20 条红线」「6 个阶段」「3 个组件」这类数字没有对应的代码字面量，
本条不管。实测这类在 330 份文档里约 6900 处——**占了绝大多数**。

### 4.4 布尔型常量不判

`KHY_X = 1` 表示「开关打开」，不是可比的数值。实测这类占常量主张的大头
（`KHY_CC_TUI` 46 处、`KHY_SELECT` 16 处、`KHY_FAST_STARTUP` 16 处……），
全部取值 0/1。**把它们算作漂移会把守卫变成噪声源。**

## 五、覆盖面与局限

| 覆盖 | 不覆盖 |
|------|--------|
| 文档写下「同名常量 = 数值」且代码里该常量值唯一的情形 | **运行读数类**（`R1=28`、`门禁 exit 0`）——需重跑，白名单登记后才可判 |
| 文档引用了失效行号 | 纯叙述性数字（约 6900 处） |
| —— | 布尔型常量（取值 0/1） |
| —— | 同名多值的常量 |

**实测可判定率 43/83 ≈ 52%**——即约一半的常量型数值主张机器能判，
另一半（同名多值、布尔型、代码里根本没有该常量）**留给人工**。
这个比例说明：数值漂移**不是**「全部可机检」，但**有一部分**是，
而这一部分恰好是最容易出错的那部分（多个文档引用同一常量却各自记着
不同值——它们的过期时刻各不相同，天然会分叉）。

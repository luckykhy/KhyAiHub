# [INIT-PRD-006] 企业侧切入与验证方案 —— 要不要做企业，以及怎么敲门

> **定位**：回答 `[INIT-PRD-004]` §二 留下而未决的一维——S4（私有部署者/企业团队）被裁决为「顺带承接，不专门投入」，那么**这个「顺带」什么时候允许转正、转正前拿什么敲门、敲门要花多少钱**。
> **性质**：定位层文档。不推翻 002/003/004/005 任何口径；本文只设立**条件制企业线**——出口条件不满足，S4 维持原裁决，本文作废回档。
> **证据基线**：下载基线与任务面取自 `[INIT-PRD-004]` §二（2026-09-23 实拉）；竞争与口径分层取自 `[INIT-PRD-005]`（2026-09-24 定稿）；能力盘点为 2026-09-26 现状（复现命令见附录）。
> **状态**：定稿（2026-09-26）；同日落实轮——G4 已确认 PASS（grype 消费步骤已在 `dual-channel-release.yml`，D6 记分板实测 PASS，见 §二 G4 更正与变更记录）；访谈操作层配套见 `[MGMT-PLAN-010]`。本文不新增规范、不新增守卫、不改命令面；§二 G1 的许可证轨道是**只待作者裁决的开放决定**，本文登记问题不代作决定。

---

## 〇、一句话

**企业线的现状是「底子已有，产品没有，授权没有，需求未验证」。正确路径不是先造「企业版」功能，而是先用「私有部署支持 + 年度许可（人工签发）」接 2~3 家 design partner，从他们嘴里听出真缺口，触发条件全中才允许企业线升为正式任务面，且升线必须对冲既有任务面。**

## 〇.五、为什么本文只管企业线

开发者线已在真源里有完整规划：获客动作见 `[INIT-PRD-004]` §五 阶段 A/B，对外口径分层见 `[INIT-PRD-005]` §五，其中首跑安装（BUG-017）是一切获客的前置条件（005 §六）。开发者线**剩下的唯一开放决定是许可证轨道**——它同时决定外部贡献者与商业生态能不能来，与「企业能不能买单」共用同一个授权底座，故并入本文 §二 G1 一并登记，由作者一次裁决。

## 一、现在就卖得动的三样（已有资产，零新开发）

| # | 主张 | 对企业说什么 | 底子在哪 |
| --- | --- | --- | --- |
| 1 | **AI 用量成本治理** | 公司给员工买的 Claude/Cursor/国产模型席位分散、谁用了多少说不清——khy-os 收口为一个网关：路由、熔断故障转移、**按人民币计价**的用量账 | `services/backend/src/services/gateway/`（`*Adapter.js` 18 个，2026-09-24 实测口径；004 §三 记 19 属漂移，以本文附录命令实测为准）+ `tokenUsageService` |
| 2 | **数据不出内网** | 对话记录、凭据、用量账全部本地；docker compose 一键自部署；便携版可进空气隙 | README §配置与数据；`[DESIGN-DEPLOY-001]` §3.3；RUNTIME-001 零硬编码保证内网改址不改码 |
| 3 | **审计留痕** | 「谁让 AI 干了什么」可回放：审计轨迹外部质检通道不压缩不裁剪，轨迹按会话录制 | `.khy/audit-trajectory/`、`.khy/trajectory_replay/`（AGENTS.md 数据存储表）；`khy trajectory list` |

**企业话术与 S1 话术的关键差异**：对个人讲「省钱」是钩子；对企业**省钱无效**——企业不省钱，企业**控成本、过审计、满足合规**。三条的对外顺序固定为：私有合规（入场券）→ 成本治理（预算价值）→ 审计（采购清单项）。

## 三、升线触发条件（出口条件制，与 004 三阶段同构）

企业线从「顺带承接」升为「正式任务面」，以下三条**全部**满足，缺一不升：

| # | 条件 | 判据 |
| --- | --- | --- |
| E1 | **需求真实** | ≥2 家外部团队主动问询或接受访谈，且主诉落在「成本 / 隐私 / 审计」三关键词内（原话入档） |
| E2 | **有人掏钱** | ≥1 家接受「部署支持 + 年度许可」付费形态（金额不限，掏钱即真） |
| E3 | **存证合格** | 访谈纪要按规则 6（RUNTIME-008）五问格式落档，每条答案带 `source: <用户原话>`——没有出处即 `self-answered`，不算数 |

**升线后**：必须对冲既有任务面（棘轮只降不升），第一候选是 T-006 多机协作扩张（004 §五 已建议降 P3——「作者的问题不是用户的问题」）。
**升线失败**：E1~E3 于 2027-03-31 前未全中，本文归档，S4 回「顺带承接」，六个月后方可重测。

## 四、Design partner 访谈：五问清单（规则 6 格式）

访谈不是问卷。开场先交付价值（免费帮装 + 帮接现有订阅），再问下面五问；全程**只问过去行为，不问未来承诺**——「你会用吗」得到的都是客套，「过去一个月你为这件事付过什么代价」得到的才是需求。

1. **谁用？**（角色）贵司谁拍板 AI 席位的采购？谁每天真正在用 agent 干活？这两个人是不是同一个人？
2. **什么时候用？**（触发时机）上一次需要「看全公司 AI 花了多少 / 谁在用」是什么场合？当时怎么解决的？
3. **现在的替代做法是什么？**（必要性证明）人工拼 Excel？各部门各买各的？云厂商控制台凑合？——对方要能说出替代做法**烦在哪里**，痛点才成立；如果说「还能忍」，不是需求。
4. **成功长什么样？**（验收判据，必须落到「命令 + 期望输出」）例：`khy gateway report --team --month` 出按成员人民币小计，会计能直接照着做账。**对方说不出口径，就说明他还没想过要这个东西。**
5. **不做会怎样？**（不做清单）对方自己绕过去的成本是多少人月？

**存证规范**：纪要落 `.khy/feedback/<访谈编号>/requirement-5q.md`，每条答案附 `source: <用户原话（谁/日期）>`。
**禁止清单**：访谈中不得谈路线图、不得承诺功能、不得演示未验证能力（BUG-017 修复前连安装演示都有翻车风险）。
**操作层配套**：找谁、怎么约、E1/E2 怎么判、纪要三件套模板——执行模板真源见 [`[MGMT-PLAN-010] design-partner访谈工具包`](../../08_MGMT_项目管理/MGMT-PLAN/[MGMT-PLAN-010]%20design-partner访谈工具包.md)，本节只留语义。

## 六、风险登记：企业线的三种输法

| # | 输法 | 早期信号 | 应对 |
| --- | --- | --- | --- |
| **RE1** | **单人项目信任墙**——采购第一问 SLA 与项目存续，任何回答都削弱个人版叙事 | 意向方要求「公司主体/合同抬头/责任条款」 | 前期只卖**服务**（部署支持）不卖产品 SLA；E2 到手再谈主体问题 |
| **RE2** | **企业需求绑架个人主线**——partner 开始点单 SSO/工单/审批流，产能被定制掏空 | 任何一次「做了这个我们就签」的交换 | §三 触发条件就是闸门：E2 未成前拒绝一切企业定制开发；E2 成后每条企业需求仍走五问 + 棘轮对冲 |
| **RE3** | **许可口径漂移**——价目表与 README「书面许可」条款互相矛盾，或 D-1 裁决后文档不同步 | 企业拿 README 许可节质疑报价单 | G1 裁决落地时 README 许可节、价目表、`positioning.js`（若涉及）一次改齐，纳入版本同步门 |

# [INIT-PRD-005] 市场立足点与竞品格局 —— 七家在场者面前的定位裁决

> **定位**：回答一个问题——**Claude Code / OpenCode / ZCode / Trae / Cursor / WorkBuddy / Abu 都已在场，khy-os 凭什么立足？**
> **性质**：定位层文档。不推翻 [`INIT-PRD-002`]([INIT-PRD-002] 项目-定位.md)（对外叙事）、[`INIT-PRD-003`]([INIT-PRD-003] KhyOS 的核心-定位口径单一真源.md)（核心口径 A⊂B）、[`INIT-PRD-004`]([INIT-PRD-004] 用户定位与增长路线.md)（用户与增长节奏）；本文只补 004 未覆盖的一维：**竞争维度的立足判据**。
> **证据基线**：2026-09-24 工作树实测（khy-os 侧全部数字可复现，命令见附录）；竞品事实取自公开资料（发布方公告/官方文档/公开检索），仓内既有对标明细见 [`MGMT-RPT-016`](../../08_MGMT_项目管理/MGMT-RPT/[MGMT-RPT-016] 竞品情报图谱.md)，本文**只引用不重复**。
> **状态**：定稿（2026-09-24）。本文不新增规范、不新增守卫、不改任何代码。

## 〇、一句话

**用户列的 7 个名字不在同一层：编码系与办公系都是「智能体应用层」，khy-os 唯一站得住的位置在「应用层之下、模型层之上」那一格。但那一格今天没有市场——基线下载量说明立足点目前≈0。所以立足不是靠「我在另一层」自证，而是靠「用一个应用级钩子把人骗进来，再用应用层之下那一格把人锁住」。**

三句话展开：

1. **别在别人的主场打。** 「谁更会写代码」这一维度上 khy-os 结构性打不过 Anthropic 与腾讯（见 §三）；把立足点建在这上面＝必输。
2. **要打的是一场对手结构上不能打的仗。** 有四件事竞品不是「暂时没做」而是「做了就反自己的商业模型」（见 §四）。
3. **先修「一次安装」，再谈「市场立足」。** 当前首跑实测不成立（BUG-017），任何定位话术都还没有载体（见 §六）。

## 一、先分层：7 个名字其实横跨 3 层，只有 1 层真正重叠

按「它靠什么挣钱」分层，而不是按品牌或形态：

| 层 | 玩家 | 靠什么挣钱 | 与 khy-os 的关系 |
| --- | --- | --- | --- |
| **L4 应用层·编码** | **Claude Code**（Anthropic 自营） | 模型订阅 | **正面重叠**（同为终端内编码 agent），但它是「模型厂商自营」——不可能帮你接别家的订阅 |
| | **Cursor** | 编辑器订阅 | 形态锁在 IDE，非终端赛道 |
| | **Trae**（字节） | IDE + SOLO 订阅 | 同上，中文市场直接竞争 |
| | **ZCode**（智谱 Z.ai，ADE） | 智谱模型 + 工具聚合 | ⚠ **最危险的一个**：它已把 Claude Code / Codex / Gemini 收进同一个桌面界面 ⇒ **「多工具聚合」这半个差异已被国内厂商做掉** |
| | **OpenCode** | 开源 + 社区 | 形态与定位最近，但无网关层、无订阅套利 |
| **L4 应用层·办公** | **WorkBuddy**（腾讯） | 云 + 办公套件 | ⚠ **平台级对手**：2026-09 已把 Agent 底座对外开放，并做办公套件化（文档/知识库/网盘/设计同体系） |
| | **Abu-Cowork**（阿布，Apache 2.0） | 开源桌面助手 | ✓ **不是对手，是资源**——仓内已有把它生成成 khy 工具的完整案例（见 §四·3） |
| **L2 网关层** | （ZCode 部分进入 / WorkBuddy 部分进入） | — | khy-os 的 **18 个 `*Adapter.js` + 4 层容错**在这一层 |
| **L1 运行时层** | **（空）** | — | khy-os 的 **壳 → 漏斗 → 网关**（`[INIT-PRD-003]` 口径）在这一层，**当前无对手** |
| **L0 内核** | （空） | — | khy-os 的实验分支（`[INIT-PRD-003]` §4.1 已裁定不占核心席位） |

**这张表是全文的支点**：khy-os 同时出现在 **L4 / L2 / L1**。这是它最大的机会，也是它最大的病——**用户只在 L4 认它，而它把约 67% 的产能投在 L1/L2**（`[INIT-PRD-004]` §一 的任务面盘点）。

### 2.1 由这张矩阵得出的两条硬结论

**结论 A：在「编码交付力」上竞争＝必输，且是结构性必输。**
对手是模型厂商自营（Anthropic 拿得到未发布模型的内部通道）与平台公司（腾讯有整建制的工程团队）。khy-os 是单人/小团队项目，**迭代速度与评测资源不在一个量级**。把「比 CC 更会写代码」当卖点，等于把战场选在对手的主场且地形对我最不利。

**结论 B：ZCode 的出现把「多工具聚合」从差异降级为及格线。**
2025-12 智谱发布 ZCode（ADE），把 Claude Code / Codex / Gemini 整合进同一桌面界面 ⇒ 「我支持多模型」**不再是差异**。
⇒ **立足点必须从「多」升级为「中立」**：ZCode 的聚合是**智谱生态的入口**（聚来是为了导向自家模型），khy-os 的中立是**不站队任何一家**（聚来是为了让用户省钱，khy-os 不从中抽成）。**这是「聚合」与「中立」的区别，也是唯一还剩下的区别。**

## 三、诚实面对重叠区：终端内编码 agent

这一仗在打，而且目前是输的。三条证据：

| 证据 | 出处 | 含义 |
| --- | --- | --- |
| 交付力对标 40 / 110 | MGMT-RPT-016 §4.1 | 差距是**数量级**的，不是打磨能补的 |
| PyPI 近一日/周/月 **5 / 92 / 173**；npm 近周/月 **12 / 61** | `[INIT-PRD-004]` §二（2026-09-23 实拉） | 真实用户规模≈作者本人 + 少数尝鲜者 |
| 首跑 10 分钟承诺实测不成立（慢网 8.8 分钟 + bundled node_modules 缺失需首跑补装） | **BUG-017（open）** | **连「装得上」这一关都还没过** |

**判读**：在这个重叠区里，khy-os 能赢的**不是能力，是立场**——「我不属于任何一家模型厂商，所以我能替你省钱」。立场型差异的传播力**远大于**能力型差异（能力要跑分，立场一句话就能说清），这也是唯一能在单人产能下成立的竞争方式。

## 四、结构性不重叠的四件事（立足点候选，按可证伪度排序）

### 4.1 模型中立 → 订阅套利（**唯一能用「钱」证明的差异**）

| 项 | 内容 |
| --- | --- |
| **判据** | 「直连官方价 vs 实际花费 = 省了 ¥X」的月度报告。数字能截图，就是真的 |
| **现状** | 网关已有 18 个 `*Adapter.js` / 65 个文件（含大量订阅态 relay 型）；`tokenUsageService` 已按人民币计价。**只差最后一公里**：报告本身（T-026） |
| **CC 为何做不到** | Anthropic 的收入就是自家订阅。帮你省掉别家的钱可以，帮你省掉**它自己的**钱＝自断 |
| **ZCode 为何做不到** | 聚合的目的是把流量导向智谱模型，套利方向与它的商业模型相反 |
| **WorkBuddy 为何做不到** | 卖的是套件席位，接别家订阅＝把用户推向竞品 |

### 4.2 形态中立 → 随身性（**唯一的「wow 时刻」**）

| 项 | 内容 |
| --- | --- |
| **判据** | 一段「在微信里发一句话，agent 干完活回来汇报」的录屏，30 秒内可传播 |
| **现状** | T-001（微信 ilink 闭环）/ T-013（手机 APK）/ T-022（四端同步，004 §B2 已裁定砍成「手机↔桌面同会话续聊」最小闭环） |
| **竞品为何做不到** | Cursor / Trae / ZCode 的形态锁在 IDE 或桌面；CC 锁在终端。**形态锁是它们的商业模型，不是疏忽** |

### 4.3 可吸收第三方 agent → 「插座」心智（**唯一有仓内案例的架构级差异**）

这一条是本文相对 `[INIT-PRD-004]` 的**净增量**，也是最难被抄的一条。

| 项 | 内容 |
| --- | --- |
| **机制** | **CLI-Anything**：`khy app cli-gen <源码包> --runtime node` 七阶段流水线，把**任意第三方应用**生成成 khy 的 App + Tool + Skill，AI 对话里可直接调用 |
| **仓内案例** | [`OPS-MAN-006`](../../07_OPS_运维/OPS-MAN/[OPS-MAN-006] cli-万能接入-abu-案例.md)：**Abu-Cowork 已被接入**——`khy app cli-invoke abu agent run / skill run / schedule create …`，AI 对话可自动调用 `cli_anything__abu` |
| **为什么这是架构级** | 竞品之间是**零和**的（Cursor 不会调 Trae）；khy-os 是**寄生/共生**的（khy-os 调 Abu、调一切）。对手要复制它，得先把自己从「产品」改造成「宿主」——那是**组织与商业模型级**的改动，不是排期能解决的 |
| **判据（可证伪）** | 任选一个在场者，能否在 1 小时内 `khy app cli-gen` 成工具并跑通一次调用。**能 → 「插座」成立；不能 → 说明这只是叙事不是能力** |

> ⚠ **风险提示**：`[INIT-PRD-004]` §三 已裁定「平台/OS 心智是留存故事、不是获客故事」。本文**维持该裁定**：§4.3 是**留存与护城河**，**不得**写进 README 首屏或获客话术。首屏只讲 4.1 与 4.2。

### 4.4 私有与可迁移（对 S4 是刚需，对 S1 是加分）

数据全本地、便携版、`khy doctor`、source-available。竞品里只有 OpenCode 与 Abu 同侧；WorkBuddy / CC / ZCode 的云端属性是它们的商业模型，**不可能反向**。

### 4.5 四条的地位排序（不许并列）

```
4.1 订阅套利   ← 获客钩子（能用钱证明，30 秒能说清）        【阶段 A】
4.2 随身性     ← 传播素材（唯一 wow，唯一能出圈）            【阶段 B】
4.3 吸收第三方 ← 护城河（架构级，对手抄不动）                【阶段 C，不入获客话术】
4.4 私有便携   ← 加分项 + S4 刚需（不专门投入）              【顺带承接】
```

## 五、立足点结论（一句话可对外）

> **khy-os 不跟任何一家比「谁更会写代码」。它做的是「让所有 AI 都归你调度」的那一层：一个终端吃遍你所有的 AI 订阅，自动省钱、自动容错；微信和手机上随时使唤它；任何第三方 agent 都能变成你的工具。**

与 `positioning.js` 真源（`[INIT-PRD-004]` §八）的关系：**前两分句完全一致（`tagline` / `oneLiner` 不改）**；本文只是把第三分句「任何第三方 agent 都能变成你的工具」**登记为护城河条款**，明确它**不进横幅、不进 README 首屏**。

**对外口径分层（避免又一次口径漂移）**：

| 场合 | 说什么 | 不说什么 |
| --- | --- | --- |
| README 首屏 / 横幅 / `khy about` | 一个终端，吃遍你所有的 AI 订阅 | OS、插座、平台、内核 |
| 种子用户一对一 | 月度省钱报告 + 微信使唤录屏 | 架构、层级、适配器数量 |
| 技术社区/开源圈 | CLI-Anything 的架构思路（`OPS-MAN-006`） | 省钱（技术人不为省钱买账） |
| 投资人/合作方 | L1 运行时那一格当前无人 | 具体下载量（5/92/173） |

## 六、残酷前提：立足点现在≈0，先修「一次安装」

**任何定位话术在「装不上」面前都是空谈。** 当前三处硬伤：

## 七、风险登记：三种可能输掉的方式

| # | 输法 | 早期信号 | 应对 |
| --- | --- | --- | --- |
| **R1** | **平台级对手补齐**——WorkBuddy 开放 Agent 底座 + ZCode 已聚合多工具，若二者再补上「跨形态」，khy-os 的差异被压缩到只剩「私有/本地/开源」 | WorkBuddy/ZCode 发布「接入第三方模型」或「手机/IM 入口」 | 提前把差异重心从「多模型」移到 **4.3 吸收第三方**（对手最不可能抄的一格） |
| **R2** | **模型厂商把「多模型」做成标配**——若 CC 开放第三方 provider，订阅套利的前提消失 | CC 发布 BYO-provider / 兼容 OpenAI 协议 | 套利不是靠「CC 没有」，而是靠**跨家调度**（谁便宜走谁）；提前把 `khy gateway status`（T-027 相邻）做成「哪家稳/哪家省」的**决策界面**，而非单纯转发 |
| **R3** | **形态中立被云厂商抹平**——「微信里直接就有 agent」不需要 khy-os | 腾讯/字节在 IM 内直出 agent 能力 | 承认这一点；把 4.2 的价值从「能进微信」改为「**你的** agent 能进微信」（归属权差异，不是通道差异） |

> R1 是最可能发生的，也最致命：**平台玩家的资源是数量级的**。本文的判断是——**不要去比平台，去比「不属于任何平台」**。这是单人项目唯一可持续的立场。

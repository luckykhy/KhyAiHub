[DESIGN-ARCH-142] 用户数据安全更新与可选更新机制#

状态：提案（未实施）
范围：services/backend/src/services/updateCoordinator.js、services/backend/src/bootstrap/migrations.js、services/backend/src/cli/routerDispatchOps.js
上游依赖：无外部依赖
调研指针：本文件 §1 现状实证（全部 file:line 实测，2026-09-23）
模板合规：照 [DESIGN-ARCH-124] 体例

0. 一句话结论#

程序侧的更新管线已经闭环——检查、暂存、安装、回滚、「现在安装 / 稍后 / 跳过此版本」的用户三选全部存在且接线。真正的缺口在数据侧：迁移直接改用户数据（~/.khy），但迁移前没有数据快照、迁移失败只回滚程序不回滚数据、老程序遇到新数据没有降级守卫。这三条不补，「更新不破坏用户数据」就只是一句碰运气的承诺。

3.2 迁移声明 touches（P1 的前置纪律）#

每条 MIGRATIONS 新增可选字段 touches: ['<相对数据家的路径或目录>']：

  • 快照只复制 touches 声明的文件——不整目录复制（用户数据家可达数百 MB，见 §6 反模式 2）。
  • 未声明 touches 且 up 内有文件写操作的迁移，检查器判 error（新检查器 check-migration-touches.js，接线到 PR 门档）。
  • 存量 4 条迁移补声明：1.0.0（建目录，无写文件，可空）、1.0.1（cache/）、1.1.0/1.2.0（no-op，空）。

3.3 降级守卫（P2）#

启动时（runMigrations 入口处）比较 bootstrap_version.json 的版本与程序内置 MIGRATIONS 最高版本：

  • 数据版本 ≤ 程序版本：正常路径（现状行为，零改动）。
  • 数据版本 > 程序版本：用户在手动降级。默认拒绝运行迁移并打警告「数据来自更新版本 X.Y.Z，当前程序 W.V.U；继续运行可能损坏数据」。迁移本身照旧跳过（无 pending），但警告必须发出且写入日志——第一期不阻断启动（阻断会让回滚流程自锁），后续视事故率再收紧。

5. 诚实边界（刻意不纳入）#

不做原因
双向迁移（up/down）单向迁移 + 快照恢复比双向迁移可靠一个数量级：down 脚本本身就是新代码，同样可能有 bug，还让每条迁移的维护成本翻倍。恢复的是迁移前快照，正确性不依赖任何新代码
整个数据家的全量快照~/.khy 含缓存、会话历史等，体量不可控；且 dataHome.js:27-29 红线明确「解析器绝不搬数据」。快照范围必须由 touches 声明并经检查器守卫
自动安装（静默 apply）prefetch.js 现在只 check 不 apply——这是对的。自动安装等于剥夺用户选择权，与「用户也可以选择不更新」直接冲突
阻断式降级守卫第一期只警告不阻断：阻断会让「更新失败 → 自动回滚程序」这条自救链路自锁（回滚后的程序必然版本更低）
数据 schema 独立版本号体系bootstrap_version.json 已是事实上的数据 schema 版本（migrations.js:105-108）。再立一个版本号就是第二真源，违反本仓「不新建并行真源」红线

6. 反模式（这条路别走）#

❌ 别做为什么
回滚时先装旧程序、后（或根本不）恢复数据旧程序读到已被新迁移改过的数据 + 偏新的版本号 → 跳过补迁移，半迁移态永久化。顺序必须：先复数据快照，再回滚程序——因为恢复快照后版本文件也回到旧值，旧程序才能正确地重新走迁移
快照整个 ~/.khy 目录体量不可控（缓存/会话历史），拖慢 apply 数秒到数分钟，且违反数据家红线精神。只快照 touches 声明的文件
给「更新提示」加新环境变量开关KHY_SELF_UPDATE 已是总开关，再加一个就是第二真源；用户可见偏好应持久化到 state 文件（khy update off），env 只留给 CI/自动化场景
在 runMigrations 的 try/catch 里加「失败时自动恢复快照」迁移层不知道快照存在（分层职责）；恢复是 applyUpdate 失败路径的职责。迁移层自己恢复会在「非更新场景的日常启动」里误触发
用 pip --force-reinstall 当数据回滚手段rollbackPackage（:717-738）只管程序包。它已有的职责不动，数据恢复必须走快照

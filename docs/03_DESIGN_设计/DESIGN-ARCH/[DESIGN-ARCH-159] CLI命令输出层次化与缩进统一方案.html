《khy-os CLI 命令输出层次化与缩进统一方案》#

文档编号：DESIGN-ARCH-159
状态：提案（未实施）
范围：services/backend/src/cli/** 中 handler 层的命令输出排版（console 系）；不含 TUI ink 渲染族与模型输出卫生层
上游依赖：无（纯新建一个纯叶子模块 + 既有模块接线）
调研指针：[DESIGN-ARCH-128] 结构化输出方案（输出卫生层，本提案只消费不重复建）、[DESIGN-ARCH-122] TUI 设计族总纲（TUI 侧，本提案不碰）、[DESIGN-SOURCING-001]（B-P2 判定）
规则依据：RUNTIME-008（新机制落地阶段可校验·S1 只记录）、LAYOUT-005（新文件落点）、check-leaf-contract.js（纯叶子纪律）
取证时间：2026-09-26（全部 file:line 实测于当日工作区）

0. 一句话结论#

khy CLI 的命令输出有行级原语、没有块级原语——formatters.js 提供了 printSuccess/printTable/printDivider，但「分组标题 → 条目 → 详情 → 建议」这种层次结构没有任何抽象，导致 90+ 个 handler 各自手写缩进、各造对齐、各定截断，四个实测命令呈现四套互不相识的输出范式。本方案新建一个纯叶子模块 outputBlock.js（五原语：分组/条目对齐/详情缩进/截断/空值省略），先接三个试点命令，再渐进推广，守卫 S1 只记录。

判定：非借鉴类，豁免成立。 本提案统一本仓自身的命令输出排版，不引入任何外部项目的代码、结论或结构；formatters.js 中既有的 "Claude Code aligned layout" 注释是已落地的历史事实，本提案不新增借鉴对象。依据 [DESIGN-SOURCING-001] §3 B-P1：零借鉴 ⇒ B-P2 本就不触发（第 1 字段「借鉴对象」无从填写）。以下按七字段体例逐项据实声明，参照 [DESIGN-ARCH-149] §2 先例：

#字段声明

3. 目标形态#

3.1 新模块：services/backend/src/cli/outputBlock.js#

纯叶子纪律（check-leaf-contract.js 强制）：零 IO、确定性、绝不抛、绝不读 env、不改入参；风格参数（borderless 与否）由调用方传入。只返回 string[]，绝不 console.log——打印权在调用方（与 chatChords.js 同款纪律）。

缩进模型（单一真源常量，禁字面量）：

const INDENT = { SECTION: 0, ITEM: 2, DETAIL: 4, NESTED: 6 }; // 列，显示宽度计

五原语 API 契约：

// 1) 分组：标题 + 子行数组 → string[]；children 为空 → 返回 []（空组不渲染，钉死 P5）
renderSection({ title, children })            // → string[]

// 2) 条目：徽标列 CJK 感知对齐（内部走 padToWidth，钉死 P3）
renderItem({ badge, subject, summary, badgeWidth })  // → string（单行）

// 3) 详情/嵌套：按 INDENT.DETAIL/NESTED 缩进；超宽走 truncateToWidth + '…'（钉死 P2/P4）
renderDetail(text, { indent = INDENT.DETAIL, maxWidth }) // → string

// 4) 分隔线：宽度单一来源（终端宽派生，钉死 P6）
renderRule({ width })                          // → string

// 5) 空值省略谓词：供 handler 的数据组装用
omitEmpty(rows, predicate)                     // → rows | []

【模型路由】 共 4 条                                    ← L0 标题：bold + cyan（保留【】语言）

  • 表格型数据（如 khy modules 的模块清单）不硬套层级——cli-table3 表格是对的，保持；

  • 文案中文、不引入 emoji（沿用 formatters.js:3 与 ICON_* 表既有约定）。

6. 反模式（这条路别走）#

❌ 别做为什么
造「输出 DSL / 模板引擎」五原语覆盖全部实测病灶；YAGNI——病灶清单里没有一个需要嵌套模板才表达得了
让 outputBlock.js 自己 console.log纯叶子才可测（check-leaf-contract 拦截）；打印权在调用方意味着快照测试可以纯字符串断言
继续在 handler 里 padEnd 中文标签code unit ≠ 显示宽度，「看起来对齐」在中文标签上永远是错觉（P3 病根；必须走 padToWidth）
为「统一」把表格命令也改成缩进树表格数据的正确形态是表格；层级原语只服务「分组-条目-详情」型数据
把 markdownRenderer 搬进 handler 修 P7insights 的数据是我们自己的结构化数据，绕道 markdown 序列化再渲染是两次多余变换；块原语直接组装。只有「真自由文本」才归 markdownRenderer
一次 PR 迁移几十个命令回归面爆炸 + 归因不可能（本仓并行会话常态）；必须小步分批，每批带 before/after 快照
新增 KHY_OUTPUT_* env 做风格开关撞门预算棘轮；且 tableStyle 已是风格单一真源，再开一个门=第二个真源

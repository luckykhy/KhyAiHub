# [DESIGN-ARCH-215] khyos 安卓统一方案：人工基座与智能执行闭环

> **状态：统一设计提案，2026-11-14；不是实施完成报告。**
> **需求来源**：用户先提出「参考这些项目给做 khyos 做个参考方案」，随后要求「想好每个可能的细节，做好一个统一的方案」。参考对象为 Mika、Operit AI、DSH Go、PokeClaw、Droidance。
> **交付范围**：确定一个可分期实现、能验收的安卓产品方案；本轮不改运行时代码、不操作手机、不安装依赖、不改权限、不提交或发布。
> **证据范围**：本轮核对的是带未提交改动的工作树，不是已发布 APK。代码存在、静态接线、历史真机记录、本轮真机验证四者分开；本轮未做构建或真机测试。

## 0. 最终形态与默认决定

**一个 Khy OS APK：文件管理器是人工基座，AI 是可选协作者，Tool Host 是唯一设备执行入口；本机与电脑协作共用任务契约，模型可在手机、用户服务器或云端。** 不换成别人的 APK 壳，不把五个项目拼成五套引擎。

| 问题 | 本方案的决定 |
|---|---|
| 没有模型、账号或网络能否打开 App | 能；先进入文件工作区，在已授权范围内手动工作，不强制登录或下载模型 |
| 是否重新以聊天为唯一主页 | 否；继承 206 的文件基座，聊天与任务台作为上下文工作面 |
| 是否必须有 amoo / Shizuku / Termux | 均否；amoo 是可选驱动；产品不依赖 Shizuku；不动手机上供其他应用使用的 Shizuku |
| 是否支持 root | 本方案不引入 root 路线；shell uid 2000 与 root 必须明确区分 |
| AI 是否自行写用户文件 | 否；继承 206：先出计划、用户逐项或整批确认、再执行已确认范围 |
| 本机 Agent 是否等于离线 | 否；Agent 循环在手机，模型仍可在远端；真正离线必须同时关闭外发与外部代理 |
| 是否自动在云模型与本地模型间切换 | 不跨隐私边界静默切换；本轮路径固定，切换前说明数据去向并重新预检 |
| 能否后台不占屏 | 无界面工具可后台执行；主屏自动化占屏；独立显示 G5 仍冻结，不能先承诺 |
| Linux 是否默认安装 | 否；后置可选能力包，不能成为首屏、人工文件管理或手机 Agent 的依赖 |
| 首先建设什么 | 真实接线、统一授权、取消与对账、数据一致性、可验收的人工/智能闭环；不是先堆工具 |

**首个可交付版本的闭环**：用户选一个工作目录 → 手动完成同类操作 → AI 为该目录生成操作计划 → 用户确认 → 唯一执行入口执行 → 回读验证 → 能暂停/停止并说明剩余项。没有可核对的结果，允许报告「未知」，不伪装成完成。

## 4. 结构：三层不变，五个概念分开

```text
文件工作区 / 会话任务台 / 现有悬浮执行台
                    │ 用户意图、计划确认、取消
                 DriverRegistry
         amoo / local / pc-bridge / script
                    │ 具名工具请求与结构化事件
                 Tool Host
  身份与权限 → 调用登记 → 资源租约 → 执行 → 回读核验
        │ VFS / Android 原子能力 / QuickJS / 自有 sidecar
        └ 模型与远端传输通过既有网关，不能绕开上述执行面
```

授权与持久化是三层共用的契约，不是再加两层业务引擎。人工文件操作也经过相同的能力、路径、只读与审计检查；人工点击本身可以表达对该具体操作的意愿，不必让人工每次调用先经过模型。

| 概念 | 定义 | 不可混淆 |
|---|---|---|
| driver | 谁接收本轮意图、产出事件 | 不是模型名称，也不赋予权限 |
| model endpoint | 决策/视觉模型分别在哪里推理 | local driver 仍可调用云模型 |
| task owner | 谁推进这项任务并持有权威状态 | UI 观察者不是第二个 owner |
| execution target | 这次工具动作真正在哪个设备执行 | 电脑做计划可以只让手机做已授权子动作 |
| privacy/permission | 哪些数据可外发、哪些动作可执行 | 连接可信、用户登录、拥有 uid 2000 都不等于动作获准 |

### 4.1 用户可见的三种智能预设

| 预设 | 任务 owner | 模型 | 执行位置 | 开始前显示 |
|---|---|---|---|---|
| 手机执行 | 手机 local | 用户选定的远端或本地模型 | 默认手机 | 模型位置、可发送的文本/图像/文件、工具范围 |
| 电脑协作 | 配对的 Khy OS 远端 | 远端实际配置 | 按每个子动作指定手机/电脑 | owner、目标设备、连接权限、断线行为 |
| 完全离线 | 手机 local 或 script | 已验真的本地模型，script 可无模型 | 手机 | 禁止外发生效、本地能力就绪、不可用工具列表 |

三者只是配置预设，不是三个业务实现；另有**AI 关闭**，人工工作区不受这些预设限制。高级设置才展开五个维度，普通用户不必读架构术语。

### 4.2 驱动约束

- **local**：接回 AgentLoop 和现有网关；按实际模型能力决定工具调用可用性，不能仅凭 OpenAI 兼容路径判断。设置变更使相关缓存失效，下轮应用；运行中不偷换模型/endpoint。
- **pc-bridge**：绑定独立连接实例。远端 SSE 工具事件默认仅作显示，只有面向本设备、通过鉴权的执行请求才可调用本地工具，避免把远端已经执行的工具再做一遍。
- **amoo**：保留既有合法适配，不读取外部 App 私有密钥、历史或记忆。HTTP 路径必须证实对端确实提供兼容服务，不能因 URL 或 sessionId 前缀就声称是 amoo 模型；第三方助手不可响应时不由本地模型冒充回答。
- **script**：只有显式批准的步骤和能力；优先用既有 QuickJS/具名原子能力，不把任意 shell 文本当低风险脚本。不得把工具输出或 Markdown 代码块自动转成可执行脚本。
- 禁用驱动：禁止新任务，询问现有任务暂停/取消，待子调用结算后释放资源；其他驱动、人工工作区和历史记录仍可用。不默认清掉凭据和历史。

## 5. 首开、日常使用与能力发现

### 5.1 首开路径

1. 首屏展示文件工作区，只访问 App 私有目录和用户通过系统选择器授权的目录；未授权目录给明确占位与入口。
2. 可选设置默认工作目录，拒绝授权仍可继续。不要一次性索取存储、无障碍、悬浮窗、录音、相机和调试权限。
3. 用户第一次请求 AI 时，选择模型或电脑连接；没有配置就说明缺项，不伪造内置免费密钥。
4. 用户首次调用某类能力时解释用途并进入系统授权；返回后重新探测，不把「已打开设置」当「授权成功」。
5. 完成一个无破坏性的真实样例，例如在获准目录列文件、生成整理计划并预览；写入仍由用户确认。

### 5.2 能力状态不是一个绿色总开关

每项能力返回 `declared / supported / granted / reachable / ready` 的区分、原因和最近探测时间。例如无障碍服务存在但未开启、本地模型文件存在但未验真、sidecar 能 PING 但授权执行失败，均不得显示「可用」。这些字段扩展既有能力状态，不另建健康注册表。

**按请求做轻量预检**：当前设备/系统、目标目录、网络规则、模型工具能力、预算、任务资源互斥、用户授权。不要在首开时全量加载模型、扫描磁盘、启动桥或查询每个 provider。

### 5.3 文件上下文不自动等于上传许可

默认传给 AI 的是用户选定范围的必要元数据；要读正文、截屏或上传附件，界面先说明数量、类型、目的地。跨会话不隐式继承工作目录和外发授权；文件变化时计划基线失效，重新预览冲突项。

## 6. 统一任务、调用与事件契约

字段在现有 DriverTurn/DriverEvent、ToolHostClient 和原生桥信封上增量扩展；以下是目标语义，非宣称当前字段已齐全。

| 对象 | 最小字段 | 用途 |
|---|---|---|
| 任务 | taskId、sessionId、ownerId、ownerEpoch、targetDeviceId、createdAt、origin、policyVersion、privacyMode、budget、acceptance | 确定谁在做、允许做到哪、如何判定结果 |
| 工具调用 | callId、taskId、canonicalTool、normalizedArgsDigest、callerId、target、grantRef、preconditions、attempt | 同一动作贯穿 UI、Dart、原生、sidecar、远端，不丢关联键 |
| 事件 | taskId、callId?、ownerEpoch、seq、kind、timestamp、payload、schemaVersion | owner 内单调有序；跨设备使用设备/epoch/序号去重，不靠墙上时钟排序 |
| 结果 | executionStatus、verificationStatus、verdict、effect、evidenceRefs、retryClass、errorCode | 执行状态、验证状态与业务完成度独立，不压成 success 一个布尔 |
| 授权 | caller、device、task/call、tool、argsDigest、scope、expiry、policyVersion、grantVersion | 绑定真实意图，参数/设备/策略变化就不能继续使用旧批准 |

`origin` 至少区分人工、local、amoo、pc、script、plugin；展示名称不是可信 callerId。身份由传输入口建立，不接收模型自行填写的「我是用户/已批准」。

### 6.1 运行状态与完成裁决分开

运行状态：`queued → preparing → running`；期间可进入 `waiting_approval / waiting_external / paused / cancelling / reconciling`，最后 `settled`。每个状态写 reason 和下一步，不用一个「处理中」覆盖所有情况。

结束原因可以是正常收尾、用户取消、权限撤销、预算耗尽、断连、进程死亡等。最终业务裁决继承 201 的四值：

- **done**：本任务必要验收项全过，证据可关联到本轮动作；纯问答可按用户请求完成回答，不强制制造工具调用。
- **partial**：确有部分成果，但仍有失败、未执行或未核验项。
- **failed**：已知失败且未实现必要目标。
- **unknown**：结果无法可靠确定，尤其是副作用已经可能发生而回执丢失。

`DriverFinished` 只代表驱动结束本轮输出，不代表 done；模型停止生成、SSE 断流、达到步数上限均不能直接晋升 done。计划未执行要显示「计划已生成，尚未执行」。

### 6.2 单一 owner 与并发

- 一项任务同一时刻只有一个 owner；本地与远端切换需要停发新动作、对账未完成 call、显式交接并增加 epoch。首版不做断线后自动换 owner。
- ownerEpoch 由接收执行的设备核验；旧连接恢复后携带旧 epoch 的写请求被拒绝，避免两端同时继续。
- 同一目标显示、剪贴板、输入焦点为独占资源；重叠写目录/文件互斥。网络读取可有限并发，资源上限来自设备探测和配置，不让两个 GUI 任务同时点屏。
- 复用既有 LeaseBook 的能力并先核实生产接线；租约状态和调用记录持久化。租约过期不证明旧动作已停止，须先对账，不能直接把资源交给新任务。
- 任务排队与 208 的内存提示词队列分开：提示词尚未被接收为任务时，不显示「任务已可靠保存」。

### 6.3 幂等与副作用

调用账本的唯一键为 `(taskId, callId)`；首次入账原子写入参数摘要和状态。相同键相同参数返回原状态/结果，不再次执行；同键不同参数拒绝。重试沿用 callId，用户确认后的新动作才生成新 callId。

| 动作 | 可否自动重试 | 回执丢失后的处理 |
|---|---|---|
| 纯读取、受限探测 | 可，受预算和权限重新检查约束 | 重新读并注明新采样时间 |
| 按内容哈希写入工作区文件 | 仅能核对目标基线与结果时 | 先 stat/hash 对账，再决定是否未执行 |
| 跨文件系统移动 | 不把 copy+delete 当原子 move | 目标校验通过后才可删源；中断保留两边并列出状态 |
| 发消息、提交表单、付款、安装等外部效果 | 不盲重试 | 能读到回执则核验，否则 unknown，交人确认 |
| 任意 shell / 插件代码 | 默认不能证明幂等 | 不因 exit code 缺失而重跑；限制能力并人工对账 |

Android 进程与外部 App/网络之间没有共同事务，**不承诺 exactly-once 副作用**。能保证的是本地重复派发抑制、明确的不确定窗口和不盲重放。记录「开始执行」后崩溃，恢复时进 `reconciling`；查不清就 unknown，而不是 fabricated failed/done。

## 7. 暂停、停止、预算与恢复

### 7.1 取消必须到执行端

停止按钮 → owner 记录 `cancelling` → 不再派发新动作 → 取消网关请求/模型生成/受控 worker → 执行端返回确认或不能确认 → 收集结果并释放租约 → settled。

- 暂停默认停在工具边界；已开始的不可中断动作显示「等待本步结束」，不是「已暂停」。
- 取消 HTTP/SSE 订阅不等于取消远端任务；远端不支持 cancel 时显示「已停止接收，远端执行状态未知」，提供远端任务入口，不能立即授权本地重做。
- sidecar 增加按 callId 查询/取消的受控协议，只能终止该调用持有的子进程/进程组，不按名称杀系统进程。
- 本地模型需协作中断 token/生成循环，释放锁后才能 free 模型；不在 JNI 仍持有句柄时卸载。
- 发出的消息、已经支付的款项不能靠取消撤回。撤销是新的补偿操作，必须说明范围并重新授权。
- 用户手动接管 GUI 时，先撤销该显示的自动输入租约，再展示已确认/仍未知的最后动作；不是仅隐藏悬浮窗。

### 7.2 三种时间语义

1. **I/O 超时**：连接/单次读取/认证握手的短限时；返回具体错误，不暗示整个任务失败。
2. **无进展超时**：真正的输出分块、执行进度或工具结果推进才更新；空轮询、心跳只证明连接存活，不可无限续命。
3. **用户预算**：明确选择的时长、步数、token/费用、最大输出/磁盘使用；到达后停止新动作，在安全边界结算。强制停止活跃子进程只由用户明确取消或已批准的受控资源政策触发。

不把 213 的「每次轮询都重置超时」直接作为任务进展判据；也不沿用 sidecar 固定墙钟到点无条件强杀所有长任务的行为。无限/恶意插件计算可受声明的资源限额约束，不能以「有 CPU 活动」逃过沙箱预算。

### 7.3 恢复顺序

重新打开 App/网络重连 → 读账本 → 核对 owner/epoch → 探测权限与执行器 → 对账未决 call → 展示可恢复步骤 → 用户继续。首版不在重启、解锁、更新完成时自动恢复 GUI 点击、外发消息或写文件。

只读操作和已批准的可幂等后台工作可在明确的恢复策略下继续；仍需重新检查授权有效期、目标变化和设备状态。磁盘满、数据库不可写时禁止开始无法留账的副作用，不能先执行再赌记录会写成功。

## 8. 授权：系统权限、应用意图、外发许可三道条件

**有效授权 = Android 当前允许 ∩ Khy OS 当前策略允许 ∩ 本调用获准范围 ∩ 隐私策略允许。** 任一缺失即不执行。模型的理由、工具文本中的 `approved=true`、登录成功、原有 shell 权限都不能代替授权。

### 8.1 所有入口同一执行检查

覆盖人工 VFS、ToolEngine、ToolHost、MethodChannel、HTTP、文件信箱、AppFunctions、QuickJS/Skill、PC 派单和 sidecar。入口负责可信身份建立，最终执行点负责范围校验；不只在某个聊天按钮前弹窗。

- 能力/风险定义从既有 canonical 目录派生。Dart 与原生不得独立维护两张不一致的策略表；共享机器可读定义与跨语言黄金向量，原生执行点可重新验证同一授权，不是另起策略。
- 明确授权返回 `allow / ask / deny`；ask 必须停住等待真实用户，入口没有确认面就返回 `approval_required`，不能改成 allow。
- 安全判定不是允许吞异常的 before hook；超时、解析失败、未知权限档均拒绝并留具体原因。观察日志 hook 可失败，不可借此绕过授权。
- `via`、路径、包名、目标 display 均视作边界输入；即使 Dart 已路由，原生也要验证请求没有越过批准范围，不信任调用者自报 `via=storage`。

### 8.2 动作分级与批准范围

| 类别 | 默认行为 | 示例与限制 |
|---|---|---|
| 受限读取 | 在已授范围内可自动 | 选定目录元数据；读取正文还受隐私/敏感数据限制 |
| 可逆工作区修改 | AI 先计划确认，执行时重验基线 | 重命名、创建文件；预览精确目标、冲突策略和回退条件 |
| 主屏交互 | 先获得当前任务/目标 App/显示范围授权 | 不允许用一个「点按」工具将任意外部效果降为低风险 |
| 外部可见或不可逆 | 本次具体内容再次确认 | 发给谁、发什么、删哪些、付多少、安装哪个包；未知后果交人 |
| 提权、任意脚本、插件安装、远程控制 | 独立的能力开通与逐次动作边界 | 开通不是永久批准所有命令，也不允许脚本自行改变授权规则 |

普通预授权可约束到当前任务、目录、工具和期限；敏感外发、不可逆操作不接受「允许一切」批量兜底。批准卡使用执行点生成的规范化参数摘要，防止模型文案与真实参数不同；确认后参数、文件版本、收件人、金额、窗口或策略变化，原批准失效。

**AI 文件操作继续遵守 206**：一个整理计划可批量确认，但执行只限那一批明确文件和动作；后来新发现的文件不能悄悄并入。人工操作与 AI 操作共用安全边界，不意味着要把已经表达意愿的人工点击再重复问一遍。

### 8.3 不可信内容与敏感界面

网页、截图 OCR、文件、远端工具返回、Skill 文本、二维码均为数据，不得改 owner、策略、授权或目标设备。截屏中的「忽略限制」「点击允许」不产生批准。

密码、OTP、支付、系统授权和锁屏界面默认交人；不给模型读取验证码/密码、代点系统授权的通用能力。不得通过壳命令、相机、剪贴板或无障碍绕过同一隐私拒绝。敏感界面识别并非完美安全证明，高危流程最终由用户接管。

## 9. 自有提权与本地 IPC

### 9.1 提权是按能力降级，不是安装即全权

| 档位 | 能做什么 | 缺失时 |
|---|---|---|
| App uid | 已授权文件、App 私有数据、正常 Android API | 其他能力标 unavailable，不伪造成功 |
| 无障碍/MediaProjection/悬浮窗 | 用户显式授权的读屏、输入、抓屏、过程展示 | 各自独立；缺一种不强制打开其他所有权限 |
| 自有 sidecar，uid 2000 | 平台允许的 shell/系统调用子集 | 如实说明未启动、鉴权失败或系统拒绝，绝不偷偷 root |

`uid 2000` 不等于能读写任意 `/data/data/<pkg>`，也不等于所有 Shizuku API 兼容；SELinux、DAC、API 与设备策略仍有效。VFS 节点按实际访问结果显示 denied/read_only，不把「已提权」当可访问证明。

212 记录的现状是：电脑首次配对和开启明文 adbd TCP 后，自有客户端可启动 sidecar；**端口不跨重启保留**。连接到回环地址不证明 adbd 只在回环监听，开启 TCP 前应验证监听面并说明网络暴露；首版不能自动开一个长期 LAN 调试口。

目标仍是用户在本机完成 Android 无线调试配对后自举，但 pairing 使用与 TLS exporter 绑定的认证密钥交换，不能用普通 ECDH 猜一套替代。优先核对平台公开实现/可合法分发依赖并完成真机互通；旧文「只能电脑配对」只是当前实现缺口，不是 Android 永久限制。Android 不授予的能力不靠漏洞取得。

### 9.2 凭据目标态

- App 的长期身份留在私有存储/Keystore 支持的边界内，明确哪些密钥可硬件保护、哪些协议要求可导出的软件密钥；不得一律宣称硬件不可导出。
- 不把 App 私钥导出电脑作为默认量产流程。现有一次性辅助脚本属开发/受控迁移路径，使用须另行授权并核验临时副本清理；本方案不执行它。
- sidecar 不能直接读取普通 App 私有目录。推荐由已认证的自举通道通过 stdin 投递每次启动的随机会话密钥，双方内存持有，不写共享目录、命令行参数、日志或环境变量；这条投递及断开后的存活行为要做真机验证。
- 本地协议包含版本、双向挑战、会话 ID、单调序号、每请求认证、参数摘要和 grant 版本；返回也认证，不能把占用了同一端口的假服务当真 sidecar。
- 注销/轮换/撤权必须使旧连接不能再执行新动作；关闭旧会话并增加 epoch，不只是改 token 文件。已发生副作用按 §7 对账。
- sidecar 只接受 Tool Host 发出的有范围授权请求，不直接把网络 Bearer 或插件身份兑换成任意 shell。短请求必须有尺寸/并发限制；输出截断后仍排空或安全终止管道，不能因不读 stdout 卡住子进程。

共享路径的现有名字是否保留是迁移兼容问题，不能继续把该文件当信任锚。未鉴权文件信箱不应继续承担写操作；迁移前保持关闭该入口的设计目标，不在本轮改用户当前开关。

## 10. 数据、会话、隐私与迁移真源

### 10.1 数据各有一个权威写入面

| 数据 | 目标权威位置 | 派生/导出规则 |
|---|---|---|
| 手机任务、调用账本、批准与结果、事件序号 | App 私有事务存储 | 原生后台执行仍可记账；UI 与远端缓存为投影 |
| 手机会话、计划、附件引用 | 保留 ConversationDB API，迁往同一事务存储 | JSONL 作为按需导出，不再静默当第二个活真源 |
| 远端拥有的任务 | 远端任务服务 | 手机缓存标 remote owner + lastSeq；不能离线改成「完成」再强推 |
| 登录/设备连接/模型凭据 | 现有安全存储与 Keystore 能力 | 正文、日志、插件包、二维码历史中不保存明文密钥 |
| amoo 适配私有状态 | 保留现有 AmooTurnStore 的领域用途 | 只通过关联 ID 映射到通用任务，不让其同名字段成为第二个通用裁决者 |
| 模型与大附件 | 私有/用户明确选定的存储区 | 按内容哈希引用；模型可再下载，不混入默认会话备份 |
| 插件私有数据 | 195 规定的每插件作用域 | 不能读取别的插件、会话凭据或主账本 |

**实现选择**：使用已有 SQLite 技术栈，不引入另一套数据库依赖。通用任务账本由 Android 原生主进程内的单一服务写入，复用桥/MethodChannel 暴露；Dart 只通过保留的 facade 访问。这样 Flutter 页面退出时原生 BridgeService 仍能记账。原生组件共用同一写入服务，sidecar 只回结果、不直接写 App 数据库；数据库迁移也只有一个 owner。

逻辑表至少包含任务、调用、事件、批准、会话和附件引用；去重、状态更新与事件追加在同一事务内完成。并非要求把所有历史私有表合并重写，先完成对外语义与原子写入。若实测当前进程模型不同，先修正写入权属设计，禁止 Dart/native 双方各自升级同一 schema。

### 10.2 持久化与展示

任务接收、授权、派发前记录、工具结果和终态必须持久化后再对外确认。token 流可合并成段持久化，界面显示的临时 delta 不作为副作用凭证；崩溃允许丢少量未落盘的展示文本，不允许忘掉已执行动作。

附件先写临时文件并核对长度/摘要，再原子发布引用；引用计数清理必须考虑其他会话。磁盘不足时优先停新下载/新副作用，不静默删历史；清理前显示会删除什么。

### 10.3 隐私档位

- **完全离线**：本任务所有 Khy OS 管理的网络出口禁止非本机访问，包括模型、MCP、遥测、更新检查和自动下载；必须事先准备模型和资产。外部 App/助手不能被 Khy OS 保证断网，严格离线任务不委托其进行可能联网的动作。
- **指定服务**：允许明确的模型/电脑/MCP 目的地和数据类别，发送截图与文件前可预览。换目的地或增加数据类别需重新授权。
- **电脑协作**：不等于公网云，也不等于本地隐私；远端可能再调用云模型，必须显示远端实际配置/声明与可信范围，无法证明时不标「不出机」。

出站限制放在实际网关、下载器、插件 host 和远程工具消费点；单个 UI 开关不能阻止另一个网络客户端。完全离线不声称 Android 系统或其他 App 全机零流量。禁止把用户输入中的 URL 自动当安全目的地；检查跳转、DNS 解析、私网/环回访问和凭据转发范围，具体工具需要 LAN 权限时单独授予。

### 10.4 保存、导出、删除与备份

默认不长期保存原始屏幕帧；为执行短时缓存，所需核验证据最小化、可查看、可删除。会话与结果保存在本机直到用户删除；诊断日志采用容量上限轮转，默认不含正文和 token；未经同意不上传遥测。

自动生成的旧 JSONL 属可管理镜像，删除会话时同步失效/清理并记录失败；已经由用户导出给第三方的副本无法远程抹除，删除界面说明边界。远端同步删除使用 tombstone 和确认状态，断网时显示待同步，不能宣称远端已删。

不承诺普通 SQLite 自动具备应用级加密：依赖 Android 私有目录/系统文件加密，敏感字段另用既有安全存储；如要全库加密需单独论证依赖与迁移。系统备份必须排除设备凭据和未脱敏日志；跨设备恢复后重新配对，不复制旧设备授权。导出默认脱敏，含敏感数据的备份需用户明确选择加密与恢复方法。

## 11. 电脑协作、传输与失联

### 11.1 连接建立

复用 KhyOsApi 与既有 phone/amoo 传输服务，不建设第二个远程控制后端。连接资料区分「后端地址、设备身份、任务权限、可用功能」，不存在仅凭同 Wi-Fi 或相同账号就自动授权手机。

扫码/手工配对只接受短期一次性材料；展示对端名称、身份指纹和授予范围，认证完成后换成可撤销的设备凭据。公网使用标准校验证书的 TLS，不把提权配对协议中的特殊证书处理搬进通用 HTTP。PC 的 loopback 地址在手机上指向手机自己，只有实际建立的隧道/转发才可使用该地址。

优先手机主动建立连接，不默认开放手机公网入站端口。手机普通任务不需要全局 shell token；远端登录凭据与 sidecar 会话密钥独立，不互相转发。

### 11.2 协议分层

- **现有聊天**：继续使用已存在的登录/刷新/聊天流接口，不为改名再建接口。
- **可靠任务控制**：需要 submit、status、events-after、approve、cancel 五种语义；先核对现有后端是否已有，不根据名字猜 URL。确实缺失时扩展既有服务，按 §1 显式评审 213 的无新增端点约束。
- **协商**：交换 protocolVersion、schemaVersion、可用工具版本、cancel/resume/idempotency 支持标志、数据大小限制；字段未知不能默认为全支持。
- 不支持控制协议的旧对端只提供聊天/只读观察，或经用户明确确认的非自动恢复任务；不得在 UI 承诺可停止和可续跑。

SSE 用增量 UTF-8 解码与事件缓冲，处理跨 chunk 的字符、行、空行、多行 data 和明确 done；不要把每个 TCP chunk 当完整 JSON。重连带 last acknowledged event sequence，事件去重不等于重发原始任务。数据截断、缺 seq、缺终态进入对账，不把自然 EOF 判成功。

### 11.3 断网与撤权

手机端执行租约失去有效 owner 续期后不启动新副作用；已开始动作在安全边界结算。远端独立计算是否继续由任务预先声明，首版默认断联暂停新的手机动作，禁止自动迁移成手机重做。

撤销电脑连接立即阻止新调用、撤销未消费批准，通知在途调用进入取消/对账；本地人工路径仍可用。恢复失败、token 过期、对端换证书、设备 ID 改变分别给原因；不自动接受新证书或给旧设备重发全权。

## 12. 本地模型与真正离线

### 12.1 同一原生栈，决策与视觉分别验

保留现有 KhyLlama/llama.cpp/mtmd，不因为外部项目使用另一模型就换栈。可让同一已支持的本地多模态模型承担决策与视觉，但仍分别验证两条调用链；没有工具调用能力的模型只开放问答/描述，不能显示「可自动操作」。

本地工具调用需要结构化输出约束或经验证的协议适配，统一经 Tool Host schema 检查；模型生成的 JSON 字符串不是批准。多模态、上下文长度、量化格式、工具模板、tokenizer 与 mmproj 必须匹配版本，不能独立随意替换。

### 12.2 模型生命周期

`absent → downloading → verifying → installed → loading → ready → unloading`，失败带阶段与可恢复原因。`installed` 只表示资产验真，不表示内存足够；ready 需一次真实推理探测，不等于本地 HTTP 返回 200。

| 环节 | 具体要求 |
|---|---|
| 下载前 | 展示来源、权重许可、版本、实际/声明大小、网络费用提示、可用磁盘与峰值空间预算 |
| 续传 | .part + Range；核对 Content-Range 起点/总长、ETag 或 Last-Modified/If-Range；源变更不得拼接；200 从头下，416 需核对完整对象 |
| 完整性 | 实际计算全文件 SHA-256 并比对可信清单；登记清单值不算验真；长度必须一致，缺可靠摘要不自动激活来源不明模型 |
| 激活 | 同目录 staging 完成后切 active 引用；保留上一可用版本直到新模型加载与探测成功，磁盘不足不先删唯一可用模型 |
| 取消 | 取消网络流、关闭句柄，保留可续传部分；「删除下载」另经确认，不能仅删 part 却让流继续写 |
| 卸载 | 等所有使用该模型的任务释放句柄，停止推理服务，清引用，再删文件；不删除其他模型/用户附件 |
| 本地导入 | 与下载同样做格式、大小、摘要与许可信息检查，不执行包内脚本 |

使用既有资产清单/LocalModelStore，不再另建模型下载器。模型、mmproj 与引擎兼容信息成组发布；提供「资产可用但设备不够运行」而不是崩溃循环。

### 12.3 资源控制与故障隔离

先测目标机的内存、上下文、首 token 延迟、持续推理吞吐、温度与耗电。按模型估算权重映射、KV cache、视觉输入和运行时额外内存，不以 RAM 总量一个数硬判支持。

前台交互优先；本地模型默认单任务加载/推理序列化，控制图片尺寸与上下文。热降频、低电、低存储时可暂停新步骤、缩减已告知的预算，**不自动改用云端**。模型任务的存活需要受 Android 实际限制的明确生命周期，不靠一个 Dart 页面保活。

普通 Driver 异常可在 Registry 内隔离；JNI 崩溃/OOM 可能结束整个 App。短期必须可靠记账与恢复，不能宣称完整进程隔离；若真机表明本地推理使人工基座不可用，再把现有推理模块搬至独立 Android 进程服务，保留同一模型与调用契约，不重写推理引擎。模型仅经受控服务访问，不把无鉴权 loopback HTTP 当天然私有接口。

## 13. GUI 自动化、读屏与独立显示

### 13.1 操作优先级

**具名 API/Intent/VFS → 无障碍语义节点 → 必要截图与视觉坐标**。选择能够表达同一意图且权限不更高的路径；上一条被拒绝时不得换成裸 shell 或坐标点击绕过拒绝。

每次观察绑定目标 package、window/display、旋转、尺寸、时间与有效期；执行前重新检查前置条件。屏幕已变、键盘弹出、窗口切换、节点消失、设备折叠/旋转就重新观察，不对陈旧坐标继续点击。连续无变化限定重试次数并上报，不能形成乱点循环。

UI 点击成功只证明注入成功，后续必须核验目标状态；发送/购买类不能以按钮消失当作可靠业务回执。`FLAG_SECURE`、DRM 或系统拒绝导致黑屏时明确不支持，不改安全标志绕过。

### 13.2 人接管优先

主屏自动化开始前说明会占屏，并保证停止入口不依赖目标 App 当前界面；现有悬浮窗若未获授权，使用 App 内和通知入口，但先验证通知被禁时仍能停止。锁屏后默认不发新 GUI 动作，不尝试解锁；系统权限弹窗、支付认证交人。

无障碍、MediaProjection 与悬浮窗分别授权、分别撤销；投屏授权结果不跨重启假装仍有效。系统回调发现 projection 失效，立即降级能力并暂停依赖截图的任务。

### 13.3 G5 唯一准入

继续采用 207 §10 的三项真机门槛：跨显示可访问性树、输入确实进入目标显示、目标 Activity 能在该显示承载；补验独立焦点、主屏不中招、旋转/销毁恢复和受保护内容。安卓版本或 Mika 宣传不是通过证据。

只有人显式批准探针且上述门槛通过，才进入独立显示实现；若不可达或仅部分 App 支持，保持主屏方案并列兼容表。不把「悬浮框」「AUTO_MIRROR 截屏」或隐藏窗口改名成后台屏交差。独立屏不阻塞首版交付。

## 14. 后台、系统版本与生命周期

| 场景 | 允许的行为 | 不承诺 |
|---|---|---|
| App 切到后台 | 已获准的非 UI 短任务按系统许可继续，状态可观察 | 不因 START_STICKY 就承诺永不被杀 |
| 屏幕锁定 | 无界面任务按策略运行或暂停，GUI 停新动作 | 不自动解锁、不继续操作敏感界面 |
| Doze/省电/OEM 清理 | 记录中断，重连后对账，提供用户可选的系统设置指引 | 不强制关闭系统省电或保活所有服务 |
| 系统/用户强行停止 App | 下次手动启动恢复账本和能力探测 | 不声称 receiver 可以绕过 force-stop |
| 手机重启/包替换 | 按用户配置做允许的恢复探测、显示能力缺项 | 不自动重启高危任务、不保证 adbd 端口保留 |
| 用户退出任务/关闭能力 | 取消或结算在途工作后释放模型、投屏、连接、wakelock | 不用永驻后台补偿接线缺陷 |

按实际 targetSdk 36 核对前台服务类型、启动来源、超时回调、通知与开机限制；目前 dataSync 声明不能自动覆盖永久桥、推理、投屏等所有用途。不通过轮换服务类型或反复重启规避平台限制。

前台服务只用于真实进行中的、符合类型的用户工作；可延期下载/同步使用合适的系统调度机制，是否引入相关组件在实施时核实既有依赖。后台执行器发出的进展与页面订阅解耦；用户退出页面不等于任务失去 owner。设备兼容矩阵须分别测普通后台、Doze、锁屏、force-stop，不能用一种替代另外三种。

## 15. Skill、插件与 MCP

### 15.1 三种资产三种含义

| 资产 | 能装什么 | 不能借此得到什么 |
|---|---|---|
| Skill | 提示模板、声明式步骤、工具需求 | 文本不是授权，安装后不自动执行其中脚本 |
| QuickJS 插件 | 195 选定的 JS 与明确 host 绑定 | 不是动态 Dart、不是任意 jar/dex、不是 Node/npm 运行环境 |
| MCP 配置 | 受信任端点、认证引用、工具发现与协议配置 | 配置文件不是可执行 server；stdio 仍须本机有对应受控运行时 |

沿用 195 已有每插件 context、逐次授权、网络限制等安全内核；历史真机测试只覆盖当时测试面。补齐 loader、持久化与任务总线，不把旧测试数当新安装链路验收。

### 15.2 安装与更新流程

用户选 URL/本地包 → 下载 staging → 校验来源/摘要/格式/版本 → 检查路径穿越、符号链接、解压膨胀、大小/数量预算 → 展示能力与网络目的地 → 用户授权 → 建立插件作用域 → 激活 → 最小健康探测。失败留旧版与可解释错误，不半安装。

- 清单声明是请求，不是授予。新版本新增权限默认不继承批准；工具描述变化重新标版本，不用同名覆盖冒充原授权。
- 远端 MCP 工具列表是未信任输入：命名空间、schema、数据量和超时均限制；不让工具描述修改系统提示或隐藏真实目的地。
- HTTP/Streamable HTTP 等传输按双方实际协议版本协商；旧 SSE 只在已支持的适配范围使用，不宣称所有 MCP server 通用。
- QuickJS context 的隔离不能挡住 native 引擎漏洞；无原始网络/文件/进程绑定的代码才可能被 host 限权。若开放任意系统解释器，需另行可信代码模式，不能贴「沙箱」标签后沿用低风险授权。
- 安装来源、版本、摘要与许可随资产记录；市场可搜索、可导入描述，不自动执行其他生态的 npm 安装或 postinstall。
- 卸载先停止该插件任务、撤销授权、注销能力，再按用户选择保留或删私有数据；历史调用保留版本指纹，不成为死链接或借机清掉别的插件数据。

## 16. Linux：有明确需要才安装的可选能力包

首版不实现 Linux。需要 Node/Python/编译环境的任务优先显式选择已有电脑/用户沙箱执行；不偷偷把本地任务转到外部。后来确需手机离线运行时再进入本节。

PRoot 可提供用户态文件布局兼容，但**不是内核容器、不是提权、不是安全边界**；与宿主同 UID 的任意代码不能仅靠路径前缀就声称隔离。不能保证 systemd、内核模块、Docker、所有桌面程序或后台守护均可用。

能力包沿用资产管理、任务、VFS 和授权契约，明确 ABI、上游校验和、许可证、解包预算、升级与卸载；默认不挂载公共存储/凭据目录，不启动 SSH 公网监听。CWD 来自当前工作区，挂载由用户选择。若需要可执行代码对宿主严格隔离，应评估独立 APK/UID 等真实边界；在此之前仅面向用户明确信任的代码，不开放给模型下载任意程序自主运行。

「已安装」须完成真实命令、读写、停止和清理测试，而不是仅存在 `runtime/proot` 文件。该能力不与 196 的特定云沙箱选型合并成一条强制依赖。

## 17. 界面与可观测性

沿用现有工作区、聊天和执行台，不新建一套应用导航。常驻只展示四件事：**当前工作目录、谁在执行、实际模型/设备、正在进行的动作与停止入口**；权限、日志、模型资源等进入上下文面板。

| 状态 | 用户看到的内容 |
|---|---|
| 缺少条件 | 「本地决策模型未配置；可选择模型或继续手动操作」 |
| 等待批准 | 精确对象、动作、数据去向、可撤销范围；批准/拒绝/修改计划 |
| 正在执行 | 「重命名选中项，已完成 3/8；下一项……」；总量未知则仅报告真实完成量 |
| 断连 | 「电脑连接已断；手机未启动后续动作，最后调用等待对账」 |
| 预算耗尽 | 完成项、未做项、当前副作用状态；继续需明确新预算 |
| 用户取消 | 区分「已请求停止」「已确认停止」「仍有一个结果未知」 |
| 结果 | 产物路径/回执与核验状态；不能只显示模型说“完成了” |

结构化块 → Markdown → 纯文本的渲染降级沿用 213；降级只影响显示，不丢失批准、结果码与停止入口。流式内容可折叠，敏感模型内部推理不作为验收证据或必展示内容。只展示可解释的计划、工具动作和核验摘要。

支持中文、大字体、读屏、横竖屏、软键盘与窄屏；触控目标与焦点验证走真实 App，不靠截图猜可点。通知/锁屏只显示非敏感摘要。语音/相机沿用已有能力且按需授权，不常开麦克风或摄像头。

日志用 taskId/callId/ownerEpoch 关联，记录结构化错误和真实进度；默认隐藏命令敏感参数、token、正文。问题报告由用户预览后导出，不自动把全库会话打包上传。内部健康信号与任务进展分别记，避免心跳掩盖卡住。

## 18. 包体、签名、版本与更新

### 18.1 轻量化不以虚假数字验收

分别记录 APK 下载字节、安装后占用、首次打开到可手动操作的时间、冷启动内存、模型/插件/运行时的可选占用。比较时固定 ABI、构建模式、资源收缩与功能集合；不把去掉支持设备的 ABI 称为无代价减肥。

本机模型权重、Linux 根文件系统、可选插件不随基础 APK 默认下载；已内置原生库是否可拆，先测收益与 Android 动态加载/分发约束，不先拍板搬走。arm64 原生能力与 APK 可安装 ABI 分开列出；minSdk 最终值从解析后的 manifest/APK 取得。

### 18.2 发布不可只看 build 成功

生产候选必须满足：源码/依赖来源可追溯、产物存在、实际包名/versionName/versionCode/ABI/minSdk 正确、正式签名验证成功且证书身份匹配、无调试/测试插件或秘密混入、校验和与该产物一致、可在目标设备升级安装。

当前 release 的 debug 签名 fallback 仅能标「开发构建」。方案要求正式发布入口遇到缺签名、验签器缺失、非零退出、无法解析或证书不符时拒绝发布；不是在本轮改构建配置。AAB 和 APK 的校验路径分别定义，不能以 APK 检查通过覆盖 AAB。

构建前冻结本批改动或使用可追溯的隔离快照，记录实际 revision 和未提交补丁摘要；不在长构建期间修改输入。金丝雀只用于追溯，不替代签名、许可、身份认证或漏洞防护。

### 18.3 更新与回退

首版保留用户主动查询/打开可信发布页/系统安装器确认的路径，不为「一键更新」偷加后台安装。现有链路没有下载后验证，就如实标为跳转下载，不宣称自动安全更新已完成。

若后续内建下载更新：清单经可信发布身份验证，APK 摘要、包名、版本与签名证书/合法轮换链全部校验，通过系统安装器由人确认。不同证书不能靠卸载旧版实现“升级”；卸载会丢 App 私有数据和身份，必须单独说明并授权。

Android 应用降版通常受版本码和数据 schema 限制，不能承诺安装旧 APK 即无损回滚。优先用同签名、更高 versionCode 的修复版；数据回滚从验证过的备份恢复。模型/插件回退与 App 回退分开，任何回退都不恢复已撤销的授权。

发布渠道的包安装、无障碍、广泛存储、动态代码等政策需针对实际渠道核对；本方案不保证可上所有应用商店，也不修改 targetSdk 逃避限制。

## 19. 迁移：分片可回退，不一次重写

| 顺序 | 做什么 | 防止什么 | 回退条件 |
|---|---|---|---|
| M0 | 固化真实入口、当前协议与历史数据样本；备份由用户确认 | 用 mock/空注册表证明不存在的成功 | 无运行时变化 |
| M1 | callId、caller、参数摘要、执行状态在现有信封中贯通；不先开启新写入口 | 名义统一、执行仍散落 | 旧客户端不支持关键字段时只读/拒绝写，不能静默降级 |
| M2 | 授权 broker 接到所有消费点，撤销旧共享令牌与旧连接 | 聊天有确认、HTTP/插件却直通 | 不回滚到公开令牌或 ask 自动放行；停用相关入口保持人工基础功能 |
| M3 | 原生事务账本成为手机任务权威，ConversationDB API 保留 | UI 退出丢状态、双写冲突 | 切换前校验迁移；切换后有新写入时禁止直接恢复旧快照抹掉新数据 |

历史记录保留原 ID、时间和来源；没有证据的旧成功记录标 legacy/unverified，不补造 callId、执行时间或授权。迁移重复执行必须幂等；遇到加密存储不可解密不能当空库后覆盖。

通用存储迁移先暂停相关写入、备份、变换、校验、切换读写 owner，再开放任务。不要长期 SecureStorage/SQLite/JSONL 三路活写；备份只读、投影可重建、各自角色明确。测试夹具包含中文、空会话、工具结果、多附件、旧 driver 元数据、坏行、盘满与迁移中断。

### 21.1 仪器本身也要验

真实工具目录数量必须大于零；声明集合、实现集合、实际调用集合分别核对。每条安全测试同时有合法正控制和故意触犯的负控制；若删掉授权接线测试仍全绿，该测试不能签字。比较回归看具体失败集合，不只看错误总数相同。

关键统计分别报样本数与通过数：任务达成率、未知结果数、取消确认耗时、重复执行数、迁移完整率、首开耗时、包体/内存/推理吞吐。分母必须是真实受测集合；没有设备样本不报百分比。性能先测基线再由实际用户体验定阈值，不杜撰“保证 95% 成功”。

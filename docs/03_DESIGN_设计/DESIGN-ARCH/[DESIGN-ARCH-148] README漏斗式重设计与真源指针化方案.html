0. 一句话结论#

当前 README 的骨架是「开发者文档首页」而不是「项目门面」——开发者向内容（架构、入口点表、Docker 部署、版本同步九源）占据前三分之一，潜在用户的「凭什么 + 怎么装」被淹没，且存在 7 类与仓内 README 真源规范 [DESIGN-DOC-003] 相抵的事实副本。本方案按「读者注意力漏斗」重排节序（所有人 → 新用户 → 进阶 → 开发者），把副本收敛为指针，并补齐 DOCS-004 的 T0 必答缺口。外部指南（aprilzz）与仓内规范在结构判据上同向，一切冲突以 DOCS-004 为准。

2. 借鉴提案（B-P2 七字段）#

载体说明：B-P2 明文允许载体为「PR 描述 / 看板卡片 / 提交信息正文，不必单独开文件」。本块按七字段体例齐全填写，但不占用 【借鉴提案 P-NN】 标题、不登记 PROPOSAL-ARTIFACT-INDEX.json 的 primary——该登记位是单文档建模，切换会撤下 [DESIGN-ARCH-105] P-01~P-07 的机检覆盖，净损失。本提案为 idea 级（B-P3：作者自评 + 任一评审即可），登记方式如维护者要求 formal 化，再把 primary 切换至本文档并合并登记两份 items。

  1. 借鉴对象：aprilzz.com《写好 README 的完整指南：从项目门面到开发者体验》，发布于 2026-06-09，https://www.aprilzz.com/tutorials/readme-writing-guide/（页面无版本号/commit，以 URL + 发布日期定位）。
  2. 借鉴内容：借结论 + 结构——README 是注意力漏斗（是什么 → 凭什么 → 怎么跑 → 装法 → 配置 → 开发者 → 许可）、10 秒三问、短段落与反模式清单（coming soon / 无快速开始 / README 当 CHANGELOG / 手列贡献者）、按项目类型定重点（CLI 工具重安装与快速开始）。不借任何文本、代码、图片资产。
  3. 解决的问题：khy-os README 当前把开发者内容前置（架构概览、关键入口点表、Docker Compose 详节占据正文前 1/3），「凭什么用它」与「怎么装」被淹没；同一分层描述三处重复必漂移。指向 §0 病灶表 #4 / #7。
  4. 许可证与代码性质：博客原创文章，页面未声明任何开源许可证 → 按 B-S4.1 从严：仅 idea 级采纳（方法论与节序判据），不复制任何句子、图示、徽章文案；该文自身引用的 GitHub 官方 README 指南与 makeareadme.com 同样只作思想来源、不落地文本。
  5. 借鉴方式：idea。判定依据：无可执行、无可适配、无可 vendor 的对象（纯写作方法论）；且仓内已有更强真源 DOCS-004，外部指南仅作结构印证。冲突裁决已有实例：指南建议「写完整安装说明」，DOCS-003 禁「命令全集」→ 取 DOCS-003（渠道一条可复制命令 + 指针）。
  6. 落点与现有实现对比：
    • a. 落点：README.md（已存在）；配套下沉落点 docs/07_OPS_运维/OPS-MAN/[OPS-MAN-003] ai-管理-访问与登录.md（已存在，实搜 default-admin 命中）。
    • b. 现有同类实现：搜 README 于 scripts/ci/（仅命中名称一致性与根文档白名单两门）、AGENTS.md（零命中）、docs/10_规范/（命中 DOCS-003 README 内容规范 及其索引页）。结论：本提案是「按既有 canonical（DOCS-004）治理 README + 引入外部结构判据」，不新增并行规范。
  7. 验收方式：npm run check:layout 与 npm run check-proposal-index 零新增 error；node scripts/ci/check-copyright-readiness.js 不再对 README 报 copyright-name-consistency；DOCS-003 §3 人工评审 8 项逐条过；README 内每条命令实际可执行、每个相对链接可达；GitHub 网页渲染 + npm run docs:build 后离线站渲染正常。

5. 诚实边界（刻意不纳入，逐条给原因）#

  1. 不放假截图、不编造会话输出——这是硬要求；没有真实录屏前，示例位只放真实命令表。
  2. 不做双语 / 英文 README——项目卖点即本土化（国内镜像、拼音命令、中文错误消息）；DOCS-003 未要求英文；aprilzz「中文 README vs 国际社区」之诫在此不构成冲突（目标用户即中文用户）。
  3. 不改 AGENTS.md / CONTRIBUTING.md——它们归 [DESIGN-DOC-002] 与贡献流程管辖，与 README 族互斥。
  4. 不动 kernel/ 相关叙事定位——[INIT-PRD-003] 已裁决其为实验/教学资产；本方案只把该裁决引用为「不是什么」。

6. 反模式（这条路别走）#

❌ 别做为什么
为「对齐外部指南」把 README 改成双语或英文项目定位即本土化；两份语言版本会互相漂移成双真源
把目录树「压缩后保留」在 README半棵树仍是副本，下次 check:layout 调整照样漂移；指针 + 七层一句话才是一劳永逸形态
借机在 README 里加「coming soon / 规划中」功能aprilzz 点名的坑；DOCS-003 §1.5 也禁进度与临时说明进 README
用手写数字徽章补 License 或版本信息DOCS-003 §1.2 例外②只允许外部服务实时取值；License 用无数字静态徽章
只删 Docker / 管理员段不落指针能力被删而非下沉；且「删除不夹带」精神上违反 B-L2 的分步纪律
按 aprilzz 的「库 / SDK」模板补完整 API 文档进 READMEkhy-os 的 API 文档真源在 docs/，README 只给指针；抄内容 = 第二真源
为消掉版本徽章去改 pyproject.toml / npm 清单病灶在 README 的手写徽章，不在版本真源；动真源属于把药开在了别的器官上

7. 验收方式#

  1. npm run check:layout / npm run check-proposal-index：零新增 error（对照改前基线各跑一次）。
  2. node scripts/ci/check-copyright-readiness.js：copyright-name-consistency 明细中不再出现 README.md。
  3. DOCS-003 §3 人工评审 8 项逐条过：禁项 / 命令可达 / 路径可达 / 档位节齐备 / 首屏 / 台账污染 / 命名与孪生 / 指针有效性。
  4. 命令可达：README 中每条 khy 子命令与 npm run 脚本在写作时实际可执行（khy --help 与根 package.json 抽查）。
  5. 链接可达：文内相对链接逐个打开验证（含含 %20 的中文路径深链）。
  6. 渲染：GitHub 网页 + npm run docs:build 后离线文档站；本文档落盘后须重跑 npm run docs:build 生成孪生 .html 并重生成 00_INDEX。

会话轨迹问题盘点与修复方案#

状态：执行中（2026-09-28 启动）。本档是修复方案的单一真源，随各阶段落地在「落地记录」节回填。
依据：2026-09-28 对 .khy/ 会话轨迹三层（真实工作会话 / 轨迹机制自测会话 / 任务与审计记录）的全量分析。

约束：修复类改动按规则 5（修复先复现）落四件存证；Bug 走 BUGS.json 状态机；不自动 commit/push（红线 R1）。

一、先说结论#

对 Khy OS 会话轨迹（.khy/sessions/ 334 个会话、.khy/trajectory_replay/、.khy/feedback/ 278 项任务记录、.ai/hq/BUGS.json 17 条）的盘点发现：

  1. 真实问题最集中的层是任务/审计记录层（hci 审计 45 项 + TUI 缺陷清单 22 项 + BUGS 17 条），不是会话层；
  2. 真实工作会话里暴露的产品缺陷有 6 族（工具计数失真、LoopWarning 误伤、shell 转义、桌面路径、压缩不可感知、headless 工具路由）；
  3. 轨迹机制自测（d3-*、replay ledger）全部通过，唯一行为级观察是 outputHash 跨 loop 不确定；但轨迹系统自身有留痕缺口（13 个会话缺 trace-chain、.khy/images/ blob 目录丢失）。

三、批次计划#

阶段 1：S 级破坏性风险（最高优先）#

  • #45：backup.js 的 _bool（约 :66）只读 options 不扫 args，-n 短选项未解析导致 dryRun 恒 false（:224），-n 语义下仍走 :237 的真删着色分支。修法：_bool 兼扫 args（handover 记录补丁已在仓库外 4 组用例验证）。验收：backup prune -n 输出预演清单且零删除；不实测真删。证据：.khy/feedback/backup-prune-dryrun-fix/。
  • #20：等 P1 修好且 -n 可信后提请人工点头再清，按规则 7 留 manifest + rollback.txt。

阶段 2：BUGS.json open 项#

  • BUG-012：footerLayout/statusPanel 把网关警告纳入宽度预算或按显示宽度截断。复现：~125 列窗口 + windsurf 停用回退警告。
  • BUG-010：修 uiBridge 接线或删死路径；按规则 5 先落 repro-before（_appRefs 恒 null 的挂载日志）。
  • BUG-006：租约（QiQiaoBan）已过期可接手。给 deepseek-v4-flash 配独立 DeepSeek provider 或从可选列表摘除；modelSubstitutionNotice 缓解层已在树上。
  • BUG-015：收敛到 backend 或声明 khyquant 侧独立维护——标记为人的裁决项，不擅自合并。

阶段 3：真实会话暴露的产品缺陷（按频次）#

  1. 工具计数失真：定位汇总聚合点，修「成功/失败」回填；复现重放磁盘清理场景。
  2. LoopWarning：区分「同参数重复调用」与「参数变化的迭代」（复用 paramsHash），只拦 paramsHash 相同的重试。
  3. shell 转义：winCommandTranslate.js 同一回归面（09-20 刚修过 UTF-8）。
  4. 桌面路径：走 Shell API（shell folders）探测，不拼 USERPROFILE。
  5. 压缩感知：压缩后输出一行明确状态（复用规则 2.6 文案）。
  6. headless 工具路由：不可达时按规则 2.2 给具体降级提示或接通 TUI 通道。

阶段 4：HCI 只报项#

  • #42 幻影建议：最小处方为订正 DataLocation.js:199 文案指向真实入口 khy storage migrate。
  • #43 步骤 2：设计逐命令选项声明表最小 schema 后分批回填（走基线棘轮）。
  • #44 短选项：A（解析器支持）/ B（删未实现广告）/ C（清死逻辑）三案需人点头，规则 6 五问先行。
  • 第三轴（REPL/斜杠/AI 工具三通道一致性）按 handover 第四节开第 11 轮，不重跑已闭环两轴。

阶段 5：轨迹系统缺口#

  • 缺 trace-chain 的小会话：确认属早期版本产物后标记豁免（伪造哈希链比缺件更糟）。
  • .khy/images/：d3 回归改在临时目录（隔离 data home）跑，不依赖本机 blob 存续；housekeeping 文档注明 blob 目录豁免清理。
  • outputHash 语义：replayLedger 文档注明不作等值断言依据。

阶段 6：复验关单#

BUG-009/011/013/014/017 各跑原复现命令（存证 repro-after），确认后回填 updated 并 closed；失败打回 in_progress 注明。

四、贯穿约束#

  • 每批独立、修复不混重构；触及 ≥4 文件或 ≥3 顶层目录的批次拆分（规则 5 处方最小化）。
  • 阶段 1–3 落地后按 CHANGELOG 判 bump（预计 ### Fixed → PATCH；若 #44 行为面扩大则 MINOR）；先写 CHANGELOG 段再 bump，G1 四源同步。
  • 全程不委派外部智能体；提交由人工执行。

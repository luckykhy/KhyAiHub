一、结论（先看这个）#

只有选中 OpenCode 的 free 模型时，才走 OpenCode 免鉴权路径。

判定链（自上而下，命中即定）：

#条件命中动作
1模型三段式前缀不是 api:opencode-zen:不进 Zen 门禁，走该通道既有鉴权/裸请求
2池 key = opencode-zen 且 isZenEndpoint(baseUrl) 为真注入 Zen 门禁头 + stream:true + 门禁工具
3模型 id 不以 -free 结尾上游 401（付费档需真实 key），不按免鉴权放行
4模型 id 以 -free 结尾免鉴权通过（Bearer public 即可 200）

简言之：endpoint 匹配 Zen SSOT → 注入门禁；模型后缀 -free → 免 401。 两者缺一，都不走「免鉴权可用」这条路径。

二、门禁四要素（已 live 核实）#

要素实现位置核实结论
HeaderszenGatekeeper.buildZenHeaders()Authorization: Bearer public、User-Agent（SSOT）、x-opencode-session/request/client/project、x-session-id；header 本身基本不限
ID 格式newSessionId() / newRequestId()prefix_ + 12 hex 时间戳 + 14 base62；session 用 descending（~(Date.now()*0x1000+1) 取 6 字节），message 用 ascending。纯 base62 / lower36 → 403；正确格式 → 200
Body 门applyZenBodyGate()stream:true 必需；tools[] 必须含名为 bash 与 read 的工具（大小写敏感，只看名字）；无调用方工具时 tool_choice:"none"，避免模型去调门禁合成工具
模型后缀上游 401 门 + 本地清单三处对齐仅 *-free 免鉴权；claude-fable-5 / gpt-6-astra / gemini-3-flash 等 → 401；mimo-v2.6-flash-free → 200

ID 算法对齐 OpenCode 官方 Identifier.create（id/id.ts）；Body 门经 mitmproxy 对官方 1.18.27 抓包逆向得到。

五、日常使用约束#

  1. 免 key：Bearer public（池 key），khy init / 网关 _doInit 自动 ensureBuiltinZen seed，跨机器 clone 后开箱可用。
  2. 模型写法：api:opencode-zen:<id>，<id> 必须以 -free 结尾。
  3. 免费档有限额：门禁为逆向（按官方 1.18.27 实现），对方改 ID 格式 / body 指纹 / 后缀白名单可能失效；失效时优先查 zenGatekeeper.js 注释与本文门禁表。
  4. 端点 SSOT：ZEN_BASE_URL 只在 constants/serviceDefaults.js（RUNTIME-001）；isZenEndpoint 容忍尾斜杠与任一侧 /v1。

七、一句话备忘#

选中 opencode-zen 的 free 模型 → 注入 Zen 门禁（头 + ID + body）+ Bearer public → 免鉴权 200；其它模型 / 其它端点 → 不走这条路径。

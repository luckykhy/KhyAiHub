[MGMT-OTHER-006] khy-os 软著申报定名与材料方案#

配套阅读：[MGMT-OTHER-005] 是本方整理的官方现行要求清单（条款真源），
[DESIGN-IP-001] 是规则 PROCESS-010 的判据真源。
本篇只记录本方产品的申报决策及其依据，不重复官方条款；凡与 005 表述冲突处，以 005 为准。
更新日期：2026-09-28（含同日三次改名与版本号往返，见文末「变更记录」）。
依据来源与本地实测命令见文末「附」。

一、定名（现行口径）#

申请表字段填法
软件全称基于执行轨迹记录与链路校验技术的AI助手平台
软件简称留空（任何精简都会引入全称之外的字；不得填「无」）
版本号V1.2.0（沿用仓库当前真实版本；仅在明示要求时才修改）
软件作品说明原创软件
开发方式单独开发
权利取得方式原始取得
权利范围全部权利
发表状态已发表（PyPI + npm 公开分发），首次发表日期填首个 wheel 的上传日

全称 22 字，落在「基于〔技术手段〕的〔作用对象〕〔后缀〕」这一已验证句式内。
全称栏不写版本号；证书连排显示为《基于执行轨迹记录与链路校验技术的AI助手平台》V1.2.0，
媒体报道的「名称V1.0」同样是两栏连排的产物，不是名称本身含版本号。

本件客体 = 平台底座本身（kernel/ platform/ services/ apps/ extensions/ 与 CLI/网关/轨迹链路校验子系统）。
khyquant 不在此件内：它是独立项目（人 2026-09-28 明示），只是连接 Khy OS 使用，
本仓 software/khyquant/ 与 khy-quant 模块是它随平台分发/接入的载体（打包事实，不是著作权归属）。
因此本件的名称、界面标题与 60 页选材均不要求覆盖 khyquant；
software/khyquant/frontend/** 里残留的产品名也不构成本件的名称一致性障碍（见 §九 与 递交核对表.md §三）。

二、定名口径（三条，后续改名按这三条判）#

  1. 软著不审创新高度。 新颖性/创造性是专利门槛；登记审的是形式合规、名称与功能相符、

代码系独立开发的表达。因此「某功能大家都能做、缺乏创新」不构成驳回理由，
不得作为改名的依据。真正的问题只有一个：名称承诺的东西能否兑现成材料。

  1. 名称里每个词的成本必须是 1 张截图。 这是本方案唯一的硬判据。

「智能体任务编排」被淘汰就是因为它要求展示一整轮工具调用链的过程画面。

  1. 平台 前必须挂「被管理的对象」或「被校验的东西」，不能只挂技术机制。

样本里所有 AI 类通过名称都遵循这一点。

样本读出的四条事实（含对本仓此前两条流传说法的否定）：

  1. 版本号普遍带，迭代靠另案登记区分（V2.0/V5.0/V6.0/V1.0.4）——「版本号不该进名称」不成立。
  2. 写「操作系统」可以通过（彩讯《…多模态智能体操作系统V1.0》）——「报软著别写 OS」不成立。
  3. AI 类通过的多是 16–24 字的描述式名称，「4–10 字最合适」在 AI 类样本里找不到支撑。
  4. 「AI助手」是被反复登记通过的标准对象词（中亦科技 / 招商证券 / 久远银海三家），不是通用词风险。

被淘汰的备选及理由（防止重走回头路）#

备选淘汰理由
基于多供应商大模型的智能体任务编排与统一调度平台「任务编排」要求演示一整轮工具调用链，材料成本最高
基于多模型适配技术的智能体任务编排与统一调度平台同上；且「多模型适配」的画面只有通道表，软件感弱
基于多模型探测与自动切换技术的AI助手平台唯一竞争者：khy gateway status 画面信息密度最高。落选原因是「探测+切换」在审查员眼里接近配置行为，而「记录+校验」明显是程序
基于分层记忆管理技术的AI助手平台代码侧最硬（memoryTier 三层保留 + 压缩 + 老化 + 1176 行溯源），但 CLI 演示不出来：khy memory 裸子命令走 printUnknown，且记忆写入是 AI 内部自动、无用户侧命令。违反第 2 条口径，直接淘汰

三、版本号：为什么是 V1.2.0#

现行决定是沿用仓库真实版本 V1.2.0，且只在明示要求时才改。支撑与后果都要记清：

  1. 填报口径无强制：005 §6.1 原文为「版本号：建议 V1.0 / 1.0 形式」，

并明确「证书版本号以申请表为准，鉴别材料页眉版本号须与申请表一致，是否带『V』也以申请表为准」。
没有任何条款要求首次登记必须 V1.0。

  1. 一条被否掉的论证（不要拿它当依据）：有说法称「首次填 V1.2.0 会因 V1.0/V1.1 缺失触发

『首次发表逻辑矛盾』而被补正」。不成立——发表状态是独立字段（选「未发表」则根本不出现首次发表日期），
与版本号字段互不推导。所谓「30–40% 补正概率」查无出处。

  1. 沿用 V1.2.0 换来的实际好处：khy about 打印的版本串天然就是 V1.2.0，

零覆盖、零修图、零「材料与实际不符」。

  1. 承担的代价（必须认）：005 §九 规定登记事项变更时版本号仅允许增加或去掉「V」。

因此这张证永久停在 V1.2.0；将来 1.3.0、2.0.0 只能另案新报，改不了这张证（见第八节）。

  1. 仓库无 v1.2.0 tag（最近 tag 为 v1.1.15），但 G1 四处真源当前均为 1.2.0，

以「工作树版本串」为准即可，不依赖 tag 存在。

四、材料一致性（退回情形「版本号不一致」的落点）#

递交件不放本文档所在处：本文档只记决策与依据；将要递交的东西与逐件状态在
evidence/06_申报材料/（用户 2026-09-28 要求：申报材料单独一个文件夹，不与原文档混放），
生成工具链在仓外 D:/Portable/软著交付/Khy-OS/06_工具/。三处分工见该夹 README §一。

005 §九把「申请表与鉴别材料页眉的软件名、版本号不一致」列为退回情形。本仓做到一致的机制是现成的：

版本串是动态读取的。 cli/handlers/about.js:55 走 require('../../../package.json').version，
src/ 下没有硬编码的应用版本字面量。因此沿用真实版本时不需要任何覆盖动作，
G1 四处真源（pyproject.toml、packaging/npm/package.json、services/backend/package.json、
packaging/modules/modules.json）保持现状即全局一致，截图零修图。

快照生成步骤#

  1. 从冻结的 commit 复制一份登记专用目录（仓库外，或落在 gitignore 覆盖的目录内）；
  2. 不改版本号，直接从此目录运行以生成截图、说明文档、源程序 60 页；
  3. 开发完成日期填该快照 commit 的日期。

之所以仍要独立目录而不是就地出材料：本仓是共享工作树，随时有进程改写文件，
登记客体必须是一个能固定下来的快照。

六、鉴别材料与说明书#

  • 源程序：超 3000 行取前 30 页 + 后 30 页，每页 50 行，末页须为完整模块结尾；

页眉印「软件全称 + V1.2.0 + 页码」（005 §5.2）。

  • 选页约束：services/sessionPersistence.js（含 verifyTraceChain）与

cli/handlers/trace.js 必须在选页内——同时满足 005 §5.2「代码需体现说明文档主要功能部分」。

⚠ 与仓外既有选材冲突，待人定案（2026-09-28 发现）：2026-09-20 那套已校准的 60 页
是「前 30 页 Python 启动器 + 后 30 页手写内核 .c/.asm」，上面这条要求的一行都不在其中
（那批 JS 当时被归入「中段·不提交」）。三条处置与代价见
evidence/06_申报材料/递交核对表.md §五；建议只换前 30 页、内核段不动，
使「名称载体的代码」与「原创硬资产」同时留在材料内。
换页眉不改页数，换选材必须重新实测页数。

  • 说明文档：按 005 §6.4，硬件环境、软件环境、编程语言、源程序量四项任何名称都躲不掉，

按实际填（Node.js + JavaScript 主体、Python 启动器、Vue 前端）。

  • 主要功能一节：本名称只需一节——「执行轨迹记录与链路校验」，配第五节那张主证据图即可闭环。

这正是它比「任务编排」版省材料的地方。

七、涉 AI 申报的额外动作#

名称含「AI」不是驳回理由（样本里三家「AI助手」均已登记通过），但需备：

  • AI 合规声明：说明训练数据来源合法，以及人类创作内容与 AI 辅助生成部分的界限；
  • 与本仓规则 PROCESS-010 的衔接：判据真源见 [DESIGN-IP-001]，与日常最相关的是

C-M3（提交信息不带 AI 作者署名） 与 C-X2（进入登记材料的代码人能解释）；

  • C-X3（第三方代码不进登记材料）：选页时确认 vendor/、*_gen.*、dist/、node_modules/ 不混入 60 页。

八、后续版本#

登记完成后产品按 PROCESS-005 正常迭代与 bump，不影响这张证效力。
因版本号变更通道只能增减「V」（005 §九），1.3.0 / 2.0.0 一律另案新报，不走变更。

补报触发条件（不要为报而报）：有实质性新功能，且该功能未被已提交的源程序覆盖。

九、待办：khyquant 第二件#

候选（须先按第二节的三条口径验证演示成本）：

  • Khy量化策略回测与交易终端管理软件

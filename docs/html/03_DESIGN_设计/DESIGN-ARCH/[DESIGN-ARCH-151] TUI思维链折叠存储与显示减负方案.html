状态：部分实施 —— P2 已落地（2026-09-26）；P4/P5（逐条点击展开 + 流式跑马灯）由用户当轮裁决新增，

0. 一句话结论#

折叠与存储机制已经存在、且默认就是折叠的——思维链全文既显示不全屏刷，也没有丢：它以「思考 · N 字」一行折叠显示、以全文存进会话 JSONL 的 _timeline 字段。截图里「乱七八糟全量平铺」的根因不在「没做折叠」，而在下表三条路径之一：

#病灶证据本提案处置
A1全局 showAll（Ctrl+E）处于展开态，thinking 全文平铺App.js:5009-5012、transcriptLines.js:205-207P1：操作引导，零代码
A2跑的是旧构建 / 旧会话回放，折叠行为未生效—P1：构建新鲜判定
A3推理文本被 adapter 并进了 text 段（非 thinking chunk），渲染层对 text 全量 renderMarkdown，无任何折叠transcriptLines.js:190-197（text 分支无折叠）；截图内容带完整 markdown 结构（标题/加粗/分层），形态是正文而非 行P3：治本点在 adapter 层归位，不在渲染层猜
G1折叠行不显示真实思考耗时：durationMs 已存进 timeline 却没人消费存：queryBridgeTimeline.js:522-537；弃：transcriptLines.js:209 只显字数P2：一行显示层改动

1.2 存储链：全文已落盘，无需新建存储#

thinking chunk (useQueryBridge.js:1993 tlAppendThinking)
  → timeline 独立条目（thinking 与 text 分段，尾部同型合并）
  → 定格时 buildTurnArtifacts：thinking 保持独立条目，真实 durationMs 随行（queryBridgeTimeline.js:1011-1058）
  → aiSession.js:153  m._timeline = artifacts._timeline
  → sessionPersistence.js:344-352  _timeline present-only 写入会话 JSONL
  • sessionPersistence.js:344-348 注释明说这是 additive contract，旧 reader 忽略未知字段。
  • 会话恢复 / /issue、/perf-issue 等 handler 都走同一份 JSONL transcript（handlers/issue.js:164）。
  • 结论：思维链「存储」这一半已经闭环——全文在盘、显示折叠。任何「再建一个 thinking 存储」的写法都是新建并行真源，直接违反本仓红线。

1.3 病灶判定方法（给使用者的一次性操作）#

  1. 在 TUI 里按 Ctrl+E：若那批文字收进 `` 行 → 属 A1，纯开关状态问题。
  2. 若无变化：查会话 JSONL 里 _timeline 的段型分布——type:'thinking' 存在 → 显示层问题；推理文字全在 type:'text' → 属 A3（adapter 把 reasoning 并进了正文通道）。

5. 诚实边界（刻意不纳入）#

不做原因
per-item thinking 单条展开（点击/Ctrl+O 逐条）不做 已推翻（2026-09-26 用户裁决，见 §4 P4）。原判断错在把「交互焦点」当成前提：其实不需要行焦点，只要投影多产出第三条平行数组 folds，命中行各自挂 onClick、由闭包携带下标即可——「纯文本行数组」契约与「屏幕行 == 数组下标」不变量都未被破坏。仍不做键盘逐条（用户裁决「仅鼠标点击」）
渲染层启发式判「这段 text 像推理」自动折叠不可测、必然误伤正文（见 §6）
新增 env 门做回滚开关P2 是单点显示改动，用「参数缺省 → 旧行为」即可，不撞 check-tui-gates.js:32 的门预算棘轮（MAX_GATES=220 只降不升）。注：2026-09-26 实测该棘轮已记 limit 227 且当前存量 232 为既有超额（非本次引入），故 P4/P5 全程复用既有门（KHY_CARD_CLICK / KHY_THINKING_DURATION）与「不传 prop → 逐字节回退」，token 数保持 232 不上涨
顺手修 §7 里那条既有红测试归因属并行会话的 decision 投影改动（transcriptLines.js:296-304 新增 decision 分支 vs 旧断言 test.js:131），与本提案无关，单独条目处理

6. 反模式（这条路别走）#

✗ 别做为什么
在渲染层用正则/关键词猜「text 段里哪部分是思维链」推理与正文在 text 通道里信息论上不可分；猜错 = 把正文答案折掉，比「显示乱」严重一个量级。归位责任在产生数据的那一层（adapter），不在消费数据的渲染层
为思维链新建独立存储文件/表_timeline in JSONL 已是单一真源（§1.2），第二存储 = 本仓明令禁止的并行真源
把 text 段改标成 thinking 段「好让它能折叠」污染数据语义：/issue、/perf-issue 等读 transcript 的消费方会把正文当推理，统计全歪
为 P2 新开 KHY_THINKING_* env 门门预算棘轮 + 会把行为修正从豁免拖进非豁免（§6.1 判据：没有「开/关都有道理」的用户可见权衡）

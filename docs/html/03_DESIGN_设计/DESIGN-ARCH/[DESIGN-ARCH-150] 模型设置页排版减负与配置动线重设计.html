[DESIGN-ARCH-150] 模型设置页排版减负与配置动线重设计#

状态：已实施（2026-09-24，P1-P3 全量落地，见 §10 实施记录）
范围：apps/khyos-desktop/src/renderer/components/settings/SettingsPage.tsx、apps/khyos-desktop/src/renderer/components/keyManager/KeyManagerPage.tsx
上游依赖：无新增（编辑能力复用既有 IPC，见 §1.3）
调研指针：DESIGN-ARCH-091（keyManager 模块来源）、DESIGN-ARCH-147（好设计十诫工程映射）
模板合规：非借鉴类，B-P2 七字段据实填「不适用」，见 §2

0. 一句话结论#

模型设置页「挤」的根因是四层垂直导航嵌套塞进 768px 容器，「难用」的根因是编辑能力三层齐全但零 UI 接线、添加表单横排溢出、配置动线断成三个 tab 无引导。修法：压掉嵌入态的内部侧栏 tab、表单改纵向对话框、编辑走现成 keysUpdate/cardsUpdate、加一条「下一步」动线状态条。

6双层标题冗余页面 header「模型设置」+ T1 内部 h2「Provider 与密钥」+ 副标题两段，嵌入态重复占高SettingsPage.tsx:67,201-204、KeyManagerPage.tsx:199-202

1.3 独立窗口通道已存在但与嵌入态互不相助#

main/keyManagerWindow.ts:16-19：独立窗口 1080×720（min 880×560），同宽下不挤。设置页嵌入态没有「在独立窗口打开」的入口，独立窗口也没有反向提示。本提案不动窗口拓扑（见 §5），只做嵌入态自愈。

2. 借鉴提案（B-P2 七字段）#

不适用。 依据：本提案是对本仓既有能力域（DESIGN-ARCH-091 落地的 keyManager 模块）的展示层修正与既有内部能力接线，不借鉴任何外部项目/代码/设计稿；keys:update/cards:update 是本仓 main 层既有 canonical。若实施中引入具体外部 UI 参考，须按 SOURCING-001 补七字段。

3. 目标形态（组件级契约）#

3.1 布局减负（一期）#

改动点契约
KeyManagerPage 新增 prop 契约embedded 为 true 时：不渲染左侧 w-52 竖 tab 栏（:74-87），改为内容区顶部横向 segmented tabs（四项横排，选中态沿用 bg-selected text-brand）；standalone 为 true 时维持现状不动

5. 诚实边界（刻意不纳入）#

不做原因
嵌入态改成「跳独立窗口」独立窗口已存在（--key-manager/菜单入口），但用户在设置页的语境是就地配置；把人踢去另一个窗口是换地方挤，不是减负
拖拽排序 provider/密钥池内已有 priority 字段但 UI 从未暴露排序意图；先解决有/无编辑，排序等真实需求出现再做
key 编辑后回显明文reveal 是一次性操作（60s 冷却 + 审计，KeyManagerPage.tsx:201 自述），编辑表单回显明文会绕过该安全模型
把本页文案迁入 i18n全页硬编码中文是既有现状，迁移属另一条目；本提案只保证新增文案不造重复键
动 T2 预设目录机制builtin-fallback 与 backend 真源的分支（:449）与排版无关，不碰

6. 反模式（这条路别走）#

✗ 别做为什么
给表单输入框继续加 min-w 或缩字号硬塞进 272px病灶是容器算术，不是字号；272px 里塞两个 200px+ 输入框在数学上不可能
新造 keys:patch/cards:modify 之类的第二个 update IPCcanonical 已三层齐全（§1.2），再建一个违反「一处真源」（main/index.ts:85-89 注释精神），且要同步改 D6 契约测试两侧
把编辑做成独立路由页（#/key-manager/edit/...）standalone 窗口 hash 路由要动 App.tsx:461 分支，弹窗/抽屉成本更低且不碰路由
为「好看」删掉 env 叠加层展示（:238-249）env 条目是真实数据（filter set 才渲染），删掉会让「这把 key 来自环境变量」失去可见性
用固定像素给 segmented tabs 定宽provider id 长度不定（agnes vs ballian-tokenplan），用内容自适应 + truncate

10.2 与方案的偏离及原因#

偏离原因
「＋ 添加密钥」按钮放在顶部操作区（与一键导入并排），非 provider 列表顶部操作集中在同一行更可发现；列表列保持纯净
一键导入按钮样式从 brand 描边改为中性描边同行出现两个 brand 描边按钮后主次不分；「＋」前缀让给了添加密钥
doAdd 成功后自动 setSelected(fProvider)新 provider 入库后立即可见其密钥列表，动线不中断
env 来源密钥不显示「编辑」keys:update 只作用于池内条目（keyStore.ts:357 按 keyId 查池），env 条目不在池内，编辑必报「密钥不存在」
T2 编辑模式隐藏预设下拉（沿用 !preset 分支）编辑时端点以卡片现存值为准，避免预设覆盖用户自定义端点

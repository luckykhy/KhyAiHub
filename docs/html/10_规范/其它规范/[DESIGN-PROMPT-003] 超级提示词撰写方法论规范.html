[DESIGN-PROMPT-003] 超级提示词撰写方法论规范#

用途：给 khy-os 的提示词资产规定「怎么设计」的方法学。适用对象：运行时系统
提示词段（[DESIGN-PROMPT-002] 的 32 段 + 17 胶囊）、works/record/ai/hq/prompts/**
的提示词资产、AGENTS.md 指令节、运行时 Prompt 模板的撰写与重构。
性质：规范性（normative）。方法学层，无机械守卫，人工评审兜底。
关系：补 Prompt 规范缺的第三条轴——[DESIGN-PROMPT-001] 管「怎么管」
（版本化/参数化/测试/注入防护），[DESIGN-PROMPT-002] 管「怎么摆」（静态/动态分区），
本文管「怎么写」（结构选型、内容三要素、生产四步法）。
出处：方法学提炼自郭泽德《超级提示词》（机械工业出版社 2026-05，
ISBN 978-7-111-81028-5）的 AFP（Auto-Flow Prompt）方法。只提炼方法与判据，
不复制原文表述——借鉴行为受 [DESIGN-SOURCING-001] 约束：思想与方法不在
B-S3 源码复制限制内，但文本表述不得照抄进本仓任何文件。

1. 要解决的问题#

khy-os 本身就是一个由提示词驱动的系统：AGENTS.md 是一份「可运行的工作环境」
（任务工作流 + 规则边界 + 状态透明契约），works/record/ai/hq/prompts/** 是给
AI 会话用的提示词资产，运行时 system prompt 有 32 段。这些资产的写法此前没有
方法学约束——写法质量取决于作者当下的手感，与代码一样需要工程方法。

本规范回答一个问题：写或改一份提示词资产时，如何把隐性判断固化为可执行的结构，
使资产可复用、可验收、可迭代，而不是一次性的愿望清单。

2. 核心公式与资产判定#

2.1 核心公式#

Prompt = Structure（结构） + Content（内容）
  • 结构是逻辑容器、执行协议、约束边界——决定输出的下限（稳定性锁死）。
  • 内容是业务变量、背景数据、参考案例——决定输出的上限（贴合度）。
  • 长期资产的结构权重远高于一次性指令：前者大部分篇幅写方法论、自检机制、

逻辑分支与质量红线，具体任务只作为一个微小变量填入。

2.2 资产三判据（入仓沉淀前自检，三条全过才是资产）#

#判据一句话判定反例（消耗品）
1可复用性换一个主体/对象依然有效：方法论是常量，具体对象是可替换变量内容与特定对象死锁，换目标即作废
2场景性定义标准（搭舞台），而非调教单次需求（调教演员）每次都要重新解释「什么是高质量」
3工作流重构内置 SOP 消灭试错，而非加速「盲猜→试错→再猜」的循环只让手工作坊更快，判断仍留在人这侧

三条全过的提示词资产才值得入仓沉淀（进 works/record/ai/hq/prompts/** 或
运行时 prompts）；只过一两条的是消耗品，就地使用、不留档。

3. 结构选型（五阶段谱系 × 场景适配）#

3.1 五阶段谱系#

阶段特征适用局限
直觉式拟人化长句、无结构、单轮低精度、探索性任务不可复现，注定平庸
框架式缩写词模型（BROKE/CRISPE/RTF）、要素填空需要稳定方法论支撑静态僵化、重结果轻过程
结构化Markdown 模块化（Role/Profile/Rule/Workflow/Initialization）长期资产的下限形态逻辑仍静态、指令过载风险
代码化伪代码：条件分支 + 循环迭代 + 对象封装高确定性要求理解门槛高、灵活性受限
自动化意图识别 + 自动编排 + 内置监督（本文 §5 四要素）复杂流程化任务对简单任务是过度工程

3.2 场景适配判定（自上而下，首个命中即停）#

同 [DESIGN-ARCH-071] 通道选择的风格：先判断场景，再选结构。没有万能模板，
编排与场景错配的两种病：过度编排（简单任务塞满约束 → 输出呆板冗长）、
编排不足（复杂任务只有情绪化描述 → 推理链断裂）。

  1. 禁止区（低认知 × 低结构：随手改一句话、问一个事实）→ 直觉式即可，

禁止套重型结构——流程成本高于收益，纯负收益。

  1. 自动区（低认知 × 高结构：固定格式重复任务——周报、纪要标准化、条款提取）

→ 轻量模板：固化的是「结构与校验」，不是「高强度思考」。

  1. 开放区（高认知 × 低结构：头脑风暴、创意发散）→ 创意版：给节奏、边界与

回收，不给硬步骤与强制格式——流程越严，创造性越弱。

  1. 统治区（高认知 × 高结构：完整商业方案、系统综述、复杂调研沉淀）→

完整方法（本文 §4–§6）：把复杂工作拆成可执行流程，把关键判断写成显性规则。

4. 内容三要素（内容 = 常量 + 变量 + 算法）#

要素定义判据
常量该场景中长期有效、被反复验证的规范、红线、方法论、审美标准不随任务更换而变；给 AI 装「职业底座」
变量本次任务独有的信息：数据、目标、受众、限制条件只捕获会改变策略的关键变量，做成「待用户填写」的槽位；缺失时按默认假设处理并显式说明
算法处理信息的可执行流程（非代码）：步骤骨架、分支规则、判断锚点、容错与收口每步有明确输入与输出；步骤是动词（执行什么），不是形容词（保持什么语气）

4.1 三维度质量判据#

  1. 逻辑颗粒度：愿望词必须翻译成参数化指令。黑名单：「更专业」「幽默点」

「高水准」「接地气」「像大厂」→ 改为可检查的机制（如「段落末尾使用预期违背
逻辑」「先看什么指标、缺什么必须追问」）。

  1. 上下文密度：关键知识以高相关、低干扰方式编排（术语、指标、误区、约束、

合规边界），防模型滑向概率最大的「平庸均值」。

  1. 判断确定性：关键步骤内置 If-Then 决策分支——什么条件走什么路径、

出现什么信号必须转弯、约束冲突时如何取舍并把取舍过程说清楚。

4.2 反幻觉与收口（硬规则）#

  • 信息缺失/冲突/无法确定 → 标「待确认」、不编造事实、以保守假设推进并在

输出中显式说明假设前提，或提问补齐关键缺口。

  • 每次交付必须收口：给出可执行的下一步（动作、命令或确认问题），不留悬空结尾。

5. 长流程四要素（AFP）与 khy-os 机制映射#

复杂、流程化、需要多轮确认的提示词资产（统治区任务），在内容三要素之上叠加四要素：

要素要求khy-os 既有机制映射
程序化运行交互权翻转：Push（人推 AI 走）→ Pull（AI 按工作流主动索取变量与确认）。长流程必须内置严格步进 + 停帧点 + 心跳信号，禁止一次性输出全部内容状态透明规则（RUNTIME-002）的「动作+目标+进度」、规则 2.6 多阶段步骤编号；状态行/仪表盘遵守 RUNTIME-004（不用滚动区）
任务工作流化经验固化成 SOP：每步是可交付的「阶段性中间件」，硬约束（完成即停）而非软引导（「请按以下步骤思考」）；工作流默认内置质检hq 提示词的工作流段；本仓「状态机把凭运气变成走程序」的一贯立场
角色赋能产出与质检分离：审计角色独立于执行角色，通过独立性约束（禁赞美、默认不通过、只给可执行的缺陷与修正）把「挑错与否决」制度化——从「好听」逼向「正确」与 RUNTIME-010 的独立性思想同源：只读角色不持写通道；单核自审 = 自己给自己发豁免，禁止
全景仪表盘持续状态刷新对抗指令稀释：每轮重申当前阶段、本轮交付物、质量把关（PASS/FAIL）、下一步动作。规范三字：简（只留方向盘级信号）、尾（放回复末尾收口）、少（一个主仪表盘，无独立功能不加分屏）khy 终端状态行的「保存/恢复光标 + 绝对定位」模式（RUNTIME-004）；AGENTS.md 指令节受 8000 字符截断约束（放置约束见 AGENTS.md）

仪表盘内容必须来自任务本身（当前阶段/下一步/验收项/禁用项），不存在万能仪表盘；
任何只增加噪声、不提升可控性的展示项都应删掉。

6. 内容编排（六种模式）#

模式逻辑适用
串行单链条逐步推进（Step-by-Step）逻辑推导、长文写作、代码生成
并行多视角独立运行后汇总创意发散、多角色评审、方案对比
串并行混合先串行建基线 → 中段并行分支 → 串行汇总收口复杂谈判、商业计划、案件分析
迭代回环生成 → 自我批判 → 优化（Generate→Critique→Refine）高精度文案、逻辑校对
锦标赛多候选 → 打分评估 → 选优或融合找最优解、重要决策
模块化调用预定义工具/规则模块，按触发条件调用长对话智能体、多任务处理

选择规则：单一目标逐步深挖 → 串行；要多角度多角色 → 并行/锦标赛；既要分阶段
又要中途分支 → 串并行混合；质量要求极高 → 叠加迭代回环；对话中持续切换策略
→ 模块化调用。复杂资产可组合，但必须写明选了什么、为什么。

7. 生产四步法（提示词资产的 SOP）#

  1. 任务框架化：把脑中的「任务思维网」压缩为粗颗粒度流程（阶段 → 关键步骤 →

判断点），并写明适用边界（适合/不适合什么场景）与核心红线。四条提炼
路径（可组合、可交叉验证）：从系统化内容提炼（图书/长文/文档中反复出现的
结构）、从多条高质量提示词提炼共识（不要只看一条——单条带个人风格与偶然性）、
从经验复述提炼（录音/纪要交给 AI 压缩命名）、从 AI 互动提炼（概念校准 →
反问补缺口 → 标准清单 → 草案 → 案例走查回写）。粗颗粒度的原因：信息量少、
逻辑断点一眼可见，避免一上来就陷进细节。

  1. 框架内容化：把框架拆到常量/变量/算法，尽量还原真实任务的分支、取舍、

例外与风险——真实任务是网状而非线性流水线，还原度不够 AI 就只能按线性脚本
机械推进。

  1. 内容结构化：装入结构容器。本仓落点：运行时提示词走 [DESIGN-PROMPT-002]

的分层（static/dynamic 分区）与 [DESIGN-PROMPT-001] 的注册表（版本/参数/
maxTokens）；hq 提示词按各自文件的既有结构。

  1. 迭代优化：v1.0 是「刚集成完的软件」，不是成品。四道工序：
    • 体检：人工逐段对照「装进去但被简化」（删分支、并步骤、弱化锚点、把硬

约束改成软建议是要重点排查的形态——目标恰恰是保留思维网的关键节点），
可再用专项审计提示词定位高危点；

  • 回归测试：固定测试用例集，防止「改好一处、弄坏另一处」——与本仓规则 5

（修复先复现）的 repro-before/after 存证同一文化：迭代要有证据，不凭感觉改；

  • 压力测试：单元（标准输入能否完整走通流程、停帧是否生效）、边缘（喂极简/

缺变量输入，验证触发「信息不足→提问补齐」分支而非编造背景硬跑）、对抗强度
（喂漏洞明显的输入，验证审计角色能稳定抓出 ≥3 个关键问题而非礼貌附和）；

  • 真实任务进化：真实使用中的纠偏反馈是进化的燃料。两条路径：用户驱动

（哪里出问题迭代哪里，不推倒重写）与系统自进化（内置进化角色：只记录→归因
→给最小补丁与回归用例，未经同意不改写整份资产）。每次迭代留版本日志
（改了什么/为什么/用什么用例回归验证）。

成熟提示词资产通常要迭代多轮（经验值 ≥10 版）才算稳定；一次写成的提示词
默认按 §2.2 判据自检，未过三条判据的不要标成资产。

8. 与既有规则/规范的关系#

文件/规则分工
[DESIGN-PROMPT-001]（规则 PROMPT-001）怎么管：版本化、参数化、长度上限、注入防护、变更流程——本文 §7 第 3 步的落点约束
[DESIGN-PROMPT-002]怎么摆：系统提示词段的静态/动态分区与 cacheKey 纪律
本文怎么写：结构选型、内容三要素、长流程四要素、生产四步法
RUNTIME-002 + 规则 2.6状态透明与步骤编号——AFP「程序化运行 + 仪表盘」在本仓的既有强制形式
RUNTIME-004终端内仪表盘/状态行的渲染边界（不用滚动区）
RUNTIME-010独立性思想同源：审计角色不得兼任执行、只读不得持写
规则 5（RUNTIME-007）修复先复现——迭代优化的「回归测试」与本仓存证文化同构
[DESIGN-SOURCING-001]借鉴边界：本文只提炼方法与判据，不复制原文表述

9. 反例#

✗ 「帮我写得专业一点」「要有高级感」              → 愿望词，无颗粒度（§4.1）
✗ 质检与产出同一角色，自审自过                    → 单核平均解 + 谄媚（§5 角色赋能）
✗ 长流程提示词一次性输出全部内容                  → 交互权未翻转，人失去控制点（§5 程序化运行）
✗ 随手改一句话也套五阶段重型结构                  → 禁止区过度工程（§3.2）
✗ 信息不足时编造背景直接跑完五阶段                → 违反 §4.2 反幻觉硬规则
✗ 把方法论照抄进本仓文件                          → 违反 [DESIGN-SOURCING-001]（提炼不照抄）
✓ 先判场景（§3.2）→ 选结构 → 常量/变量/算法（§4）→ 四要素（§5）→ 四步法生产（§7）

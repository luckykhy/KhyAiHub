[DOCS-005] 文档实现状态标注与校验#

规则卡 · 格式依据 [MGMT-STD-008] §1（frontmatter 14 字段 + 六小节）。

字段真源是 docs/10_规范/registry/RULES-REGISTRY.json（GOV-TOOL-006 校验），
本文件由 node scripts/docs/gen-rules-cards.js 生成，禁止手改（同 [MGMT-STD-007] R6 对 .html 孪生件的约束）。
正文原文在 ssot 指向的位置：docs/10_规范/DESIGN-DOC/[DESIGN-DOC-004] 文档实现状态标注规范.md。

约束#

一份文档标 IMPL-STATUS: done，其声称的实现路径必须在仓库中真实存在——搬迁过的须先过方案 P 前缀映射与同名兜底；标 todo 的文档可写尚不存在的路径（属规划非漂移）；不得以人工标记为准而不核对代码；864 份无标记文档不受本条管辖。

授予权力#

授权维护者在 S1 阶段据本守卫的候选清单自行判断是否改动文档——守卫只报告不裁决，约 10% 为已知误报（agent 基础设施与本机态目录、Windows 路径、相对片段）；授权对误报加注释豁免而不修改判据。

提供福利#

把「这份设计落码了没有」从一句无守卫的人工约定变成可判定事实——此前 127 份标记文档无一被任何脚本消费，且标记本身已被证伪（[DESIGN-ARCH-131] 首行 done 而正文写未落地、[DESIGN-ARCH-030] done 而实现已从仓库消失）；首轮 done 54 vs todo 7 的不对称证明标记携带信息；经两轮收口（误报排除 + 路径更正 + 据实改标记 + 按板块收窄适用范围）后，适用范围内 426 份 100% 已标注且 done 类漂移归零。

反例#

见 ssot 指向的真源原文；本卡不复制反例，以免与真源漂移。

校验方式#

人工评审（该规则暂无机械守卫）

例外#

范围外文档（567 份：00_INDEX_* 索引页、实施/测试/运维/管理报告、修仙学AI 叙事章节、立项与概念科普、素材）不在管辖范围；docs/html/ 孪生件排除；命名模板（<域>.js、{A,B}.js）与 node_modules 排除；.khy/.khyos/.zcode/.claude 等 agent 基础设施与本机态目录排除；superseded 文档的历史路径单列审计项、不算漂移；范围内 296 份保守标 todo 的文档真实状态仍需人工复核——批量补标只保证不撒谎，不保证判对了；内容级漂移（数值/口径/命令/错误码与代码不符）不在本条射程——git 时间戳判先后已被实测证伪，理由见 SSOT §四。

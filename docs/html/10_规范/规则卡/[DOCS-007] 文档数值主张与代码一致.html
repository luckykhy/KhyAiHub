[DOCS-007] 文档数值主张与代码一致#

规则卡 · 格式依据 [MGMT-STD-008] §1（frontmatter 14 字段 + 六小节）。

字段真源是 docs/10_规范/registry/RULES-REGISTRY.json（GOV-TOOL-006 校验），
本文件由 node scripts/docs/gen-rules-cards.js 生成，禁止手改（同 [MGMT-STD-007] R6 对 .html 孪生件的约束）。
正文原文在 ssot 指向的位置：docs/10_规范/DESIGN-DOC/[DESIGN-DOC-006] 文档数值主张校验规范.md。

约束#

文档写下 <常量名> = <值> 即构成可逐字比对的承诺，代码里该常量的值必须相同；文档引用代码位置一律给符号名、不得给行号（DOCS-004 同款约束——行号是最易漂移的副本）；文档不得声称某读数为「当前实测」而不复核。

授予权力#

授权在 S1 阶段据候选清单人工判断是否改动文档；授权对历史文档中已失效的读数加注「历史读数，采集于 <日期>」而不改写正文；同名多值（代码里该常量在两处定义不同值）时机器不判，由人工裁决。

提供福利#

补上文档漂移的最后一块——「数值型漂移此前被断言为不可机检」并不成立：文档写下 <常量名> = <值> 时，文档与代码说的是同一个名字，这就给了机器一个可逐字比对的锚点。实测首轮 83 处主张、43 处可判定、10 处不符，10/10 人工核实为真漂移——同一常量 MAX_GATES 在 8 份文档里被写成 220 或 227，而代码真值是 237，且 8 处连行号也失效（文档称 :32/:41，实为 :50）。这正是 ARCH-020 声称 R1=28 而实跑 R1=9 同类的漂移。

反例#

见 ssot 指向的真源原文；本卡不复制反例，以免与真源漂移。

校验方式#

人工评审（该规则暂无机械守卫）

例外#

与 DOCS-005/006 同范围：索引页、规则卡（生成物）、报告、叙事与科普类不参与；代码里同名常量有多个不同取值时判不出、不报；本条不执行文档里的任何命令——需重跑才能得到的读数（如 archDebtScan 的 R1/R3）不在射程，须由白名单注册表显式登记后才可跑；纯叙述性数字（「20 条红线」「6 个阶段」）无对应字面量、不判。
